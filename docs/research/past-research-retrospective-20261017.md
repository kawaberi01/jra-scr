# 過去研究の振り返り：採用に至らなかった方法と、次の研究に残す知見

作成日：2026-10-17。対象：JRAの既存研究報告・採否記録・保存済み集計。

## 1. この資料の使い方

過去に「何を考えて試し、どの条件で何が分かり、なぜ採用しなかったか」を残し、同じ試行への時間の重複を減らすための資料。

**ここに記載した不採用は、当時のデータ・方法・購入条件についての結論であり、その発想が将来も使えないという証明ではない。** 成績が悪かったもの、標本不足で判断できなかったもの、入力の制約が大きかったものを分ける。

- 数値は既存報告からの転記。今回、SQLite・SQL Serverのデータ読取、再学習、成績再計算、外部取得はしていない。
- 回収率は購入額に対する払戻の割合。購入点数・レース数・候補数は区別する。期間や券種、購入規則が違う数値の単純比較はしない。
- 「最大払戻除外」「上位3払戻除外」は、少数的中への依存を見る当時の指標。過去の採否理由として残すが、今後の研究の一律合格条件にはしない。
- 過去報告の「未使用期間」は当時の呼称。既に確認した現在、その期間を新しい未使用テストとは扱わない。過去年への外部評価と、将来へ進む評価も区別する。
- 全体の時系列は[既存棚卸し](../../.workstate/jra-srb/sqlserver-model-data-audit/progress/029-研究モデル棚卸し.md)、旧V系の版別数値は[既存の評価一覧CSV](../../.workstate/jra-srb/sqlserver-model-data-audit/progress/030-旧V系評価一覧.csv)へ戻れる。CSVは310評価記録・263版であり、263種類の独立した理論という意味ではない。

## 2. 先に押さえる結論

| 過去に分かったこと | 今後の扱い |
|---|---|
| 同じ特徴・同じ期間への閾値追加で、見かけの好成績は作れても別期間へ再現しなかった例が多い | 終了済み系列の条件微調整を一括で再開しない |
| 回収率が高くても1〜数点しか買っていない例がある | 効果なしと断定せず、当時は判断材料不足だったと残す |
| 勝率予測の改善と、馬券での利益は一致しない | 予測精度、購入選択、価格、精算を別々に評価する |
| ラップ・通過順などの観測率が学習期と評価期で大きく異なった | 今回使う入力の観測状況を対象経路内で確認し、欠測時の処理を明確にする |
| 予想家の考えを単純な数値条件へ置き換えると、本来の判断が失われることがあった | 内容・条件・役割という発想は残し、代理指標が実際に何を表すか確認する |
| 過去オッズの再構成には、当時の出馬表・取得時刻を完全に証明できない制約がある | 過去研究の成績を、そのまま発走前の実運用成績とは呼ばない |

## 7. 新しい研究へ引き継ぐ実務上の方針

1. **終了研究は、この資料・元報告・既存集計を参照して振り返る。** 元入力の再整形、全モデルの再学習、旧全21プロファイル完走を必須にしない。
2. **研究入力は既存SQL Serverに一本化する。** 移行192/192表・470,517,746行の照合完了証跡を再利用し、再取得・全量再投入・全量再検証を前提にしない。[完了証跡の整理](../../.workstate/jra-srb/sqlserver-model-data-audit/progress/034-移行完了証跡の再利用と研究への復帰.md)
3. **①入力経路確認→②最小修正の特定→③SQL限定実行→④増量研究の順で進める。** この資料作成だけで③完了や④開始とは扱わない。先に予想家由来研究、次に選定した機械学習方式へ展開する。
4. **同じ条件を再研究する場合は「前回から何が変わったか」を1行で示す。** 例：取得済みSQLで学習期のラップ観測を増やせる、欠落月を含められる、代理条件を別定義にする。データ量が増えただけで全方式を自動再検証しない。
5. 期間・候補・比較対象を結果を見る前に固定する。モデル精度、買い方、収支、欠測件数を併記し、評価後に良かった場や距離だけを新しい成功例としない。
6. 元データや全特徴量を実験ごとに複製せず、実験条件・入力版・モデル・結果・結論を残す。SQLite削除やSQL内の整理は別の判断であり、この資料自体は削除の承認・安全証明ではない。
