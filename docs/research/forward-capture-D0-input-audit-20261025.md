## 確認した結論

**未来向けの保存は存在し、事前情報・予測・結果を結合できる保存分もある。課題は過去履歴の再取得ではなく、保存された情報とD0固有の入力・評価の接続である。**

## 対象と保存の仕組み

対象は2026-10-01〜25の既存共通Store。受領凍結の基準時点は10/25 13:10:48 JST（04:10:48 UTC）。旧来の版管理保存と、サーバー受領原本が残る保存を分けた。両者の件数を足して独立標本数にしない。

現行の日次起動設定は単勝・馬連・ワイドを発走30/10/2分前、3連複を10/2分前に保存する。10/25の起動ログは予定396オッズ・504取得上限を記録しており、稼働中の収集を停止・再登録していない。古い資料のSQLite/単勝ワイドのみという説明を現状と混同しない。

## 元のD0入力との違い

| 情報 | 今回確認した保存状況 |
|---|---|
| 出馬表、馬番、性齢、枠、距離、芝ダート | 版管理と原本に存在 |
| 同時点の単勝・馬連実オッズ | 取得版と時刻を伴って存在 |
| 各馬の公式直近走 | 表形式カードにはないが、受領原本に残る |
| 元の馬ID（native horse_id） | 調べた受領カードの該当欄は0件 |
| D0の15列履歴特徴と状態 | 一般カードの直接保存欄にはない |
| D0予測時に作ったpublic_features/属性/市場 | 保存予測には存在する例があり、8件を再現できた |

結合した原本の延べ出走馬観測3,932件に直近走の枠がある。ただし15,728走枠のうち5,285枠は日付・着順/時計とも空で、日付付き直近走が1つもない出走馬観測は783件。空枠を実際の過去走数と数えず、欠測を保持する。日付の分かる枠に当日以後の日付は0件だった。

時計水準補正、相手のレーティング、長期の適性、180日出走数などは直近4枠だけで元D0と同じ値が出ると保証できない。欠けた過去を取り直す前提にも、15列を黙ってゼロ埋めする前提にもしない。現在保存できる情報で動く別入力契約を作る場合は、元D0と名前・性能評価を分ける。

結果が既存保存先へ入った後、同じrace_idで保存確率と結合できるように全ペアとモデルSHAを保持した。早期予測・過去履歴の公表時点未証明・サーバー予測受領証拠の制約は残す。旧spec415の厳格T30試験に昇格せず、まず参考予測の結果照合として扱う。自動で結果照合を開始するジョブを新設したわけではない。

## 再現性と確認

各市場の最初の受領版を選び、両観測以前の最新事前カードを結合。受領/観測が発走後のもの、説明不能な馬集合や実価格の不足は拒否する。取消はカードに明示された馬だけ除く。入力と結果を別ファイルへ保存した。

原本時点28件を除外台帳へ保持（不正馬番号12、非対応芝ダート/頭数等16）。版管理22レースも理由付きで保持（T30未保存11、頭数6、馬番号関連等5）。元の不正値を推測で修復していない。

境界テスト計5件passed。凍結原本からの再集計が内容一致し、300原本入力/177版管理T30入力の時刻・元価格・馬集合・予測/結果の対応を検算passed。D0は保存入力を元式と独立式で再計算して全保存確率と一致。版管理だけのデータにはサーバー受領証拠があると表示しない。gzipの生成時刻による圧縮バイト差は解凍内容で照合した。

主監査は`forward_capture_20261025_v4`、版管理監査は`versioned_links_20261025_v2`。初回停止や中間版は証跡であり最終集計に使わない。原本の不正馬番号を時点単位で記録する処理と、払戻の日本語券種（馬連/枠連）の区別を修正して凍結原本から再計算した。SQLの再取得や過去への外部要求は修正再計算に不要だった。
