# O1/O2時点学習データの再生成

## 生成に使ったもの

- 生成スクリプト: `scripts/build_jra_o1o2_asof_dataset.py`
- 履歴特徴量の実装: `src/jra_srb/jra_history_dataset.py`
- 実行環境: Windows、Python 3.12.11、プロジェクトの `uv` 環境
- 読み取り元: `data/jvlink/jvlink.sqlite`、`data/jvlink/odds-parsed.sqlite`、`data/db/analysis.sqlite`
- 出力: `data/training/jra_o1o2_asof_v1/{年}/races.jsonl.gz`、`manifest.json`、`excluded.jsonl.gz`

スクリプトは3つのDBを `mode=ro` と `PRAGMA query_only=ON` で開く。DBへの書き込みは行わない。出力先の年別フォルダーが既にある場合は上書きせず停止する。

生成スクリプトは現在Gitで未追跡である。別の環境でも再現するには、このスクリプトと本手順書をGitへ追加し、入力DBの同じ時点の内容を保存する。

## 再実行

PowerShellで `D:\develop\jra-scr` に移動して実行する。既存成果物を保護するため、下の例は別の出力ルートを使う。

```powershell
Set-Location "D:\develop\jra-scr"
rtk uv run python ".\scripts\build_jra_o1o2_asof_dataset.py" --source-db ".\data\jvlink\jvlink.sqlite" --odds-db ".\data\jvlink\odds-parsed.sqlite" --analysis-db ".\data\db\analysis.sqlite" --output-root ".\data\training_rebuild" --through-date 2026-09-26
```

結果は `data/training_rebuild/jra_o1o2_asof_v1/{年}/` に作られる。元の出力先を指定する場合は、対象の年別フォルダーが存在しないことを先に確認する。

## 採用条件と照合

各レースの T-30m・T-10m で、公表時刻が判断時点以前の最新O1単勝オッズを採用する。両時点の数値オッズ、着順、単勝払戻がそろうレースを `races.jsonl.gz` に入れる。O2馬連は欠けても単勝データから除外しない。履歴特徴量には対象レース前日までの確定結果だけを使う。採用外のレースと理由は `excluded.jsonl.gz` に記録する。

各年の `manifest.json` で `all_races = adopted_races + excluded_races`、月別件数、出力ファイルのSHA-256を照合する。2026年9月27日の生成結果は、2020〜2023年が採用0件、2024年が2,086件、2025年が1,092件、2026年9月26日までが1,222件だった。

`manifest.json` の `generated_at` は実行ごとに変わる。gzipヘッダーにも作成時刻が入るため、同じ入力でも圧縮ファイルのSHA-256が一致するとは限らない。比較には展開したJSONLの内容と採用・除外件数を使う。

## データ上の制約

- 2020〜2023年は対応する確定結果が分析DBになく、採用0件。2022年のO1/O2は各3,456組が正規化済みだが、着順・払戻ラベルがない。
- 2023年は原本のO1/O2が各3,456組ある一方、正規化済みは各1,051組。残り各2,405組は `odds_source_parser_coverage` に未正規化として記録されている。
- 2025年3～8月は必要な時点単勝オッズがなく、値を補完していない。月別の除外件数はマニフェストにある。
- 2024年・2025年の採用行は出馬表の発走前取得を検証できず、`historical_card_unverified` と記録している。馬体重増減と状態は入力に入れない。
- `jvlink.sqlite` の物理ファイルはWindowsの共有ロックでハッシュ取得できなかったため、マニフェストにはその理由とO1/O2チェックポイント・原本メタデータの論理SHA-256を記録している。
