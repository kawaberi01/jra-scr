# 南関競馬 リーディングジョッキーAPI・予想利用 指示書

## 目的

南関競馬の予想で、`勝ちパターン分析` の補助材料として `リーディングジョッキー` 情報をAPI経由で取得できるようにする。

この情報は本命決定の主軸ではなく、以下の補正用途で使う。

- 騎手の場適性補正
- 騎手の距離適性補正
- 騎手の馬場状態適性補正
- 短距離戦での騎手評価補強

## 前提

参照元ページ:

- https://www.nankankeiba.com/leading_kis/000000000000001.do

画面上は少なくとも以下の条件で絞り込みができる前提で実装する。

- 競馬場
- 距離
- 馬場状態
- 表示期間
- 表示順

## 実装方針

### 1. API追加

以下の取得APIを追加する。

#### 候補エンドポイント

`GET /nankan/leading/jockeys`

#### クエリ例

- `course=kawasaki`
- `distance=1400`
- `track_condition=good`
- `period=recent_3months`
- `sort=win_rate`

距離はまず実距離指定を受け、内部で南関サイトの距離条件へマッピングしてよい。

### 2. レスポンス項目

最低限、以下を返す。

```json
{
  "source": "nankankeiba",
  "course": "kawasaki",
  "distance": 1400,
  "track_condition": "good",
  "period": "recent_3months",
  "sort": "win_rate",
  "generated_at": "2026-07-07T10:00:00+09:00",
  "items": [
    {
      "rank": 1,
      "jockey_code": "xxxx",
      "jockey_name": "騎手名",
      "rides": 120,
      "wins": 24,
      "seconds": 18,
      "thirds": 11,
      "win_rate": 20.0,
      "quinella_rate": 35.0,
      "trio_rate": 44.2
    }
  ]
}
```

`jockey_code` が取れない場合は一旦省略可。ただし将来的にはカードAPIの騎手と突合できる形に寄せる。

### 3. 予想ロジックでの使い方

主軸ではなく補正レイヤーとして扱う。

#### 使い所

- `pattern_kis` の裏取り
- `pattern_kis_cho` の補強
- 短距離戦での頭候補・軸候補の微調整
- 実力接近時の順位入れ替え材料

#### 重みの考え方

- 短距離: やや強め
- 中距離以上: 補助的
- 馬の `場・距離率` が弱い場合に、騎手だけで頭固定しない
- `track_condition_rates` と方向が一致したときに評価を上げる

#### 明示ルール

- リーディングジョッキーだけで本命を決めない
- `pattern_uma.rates.(course/distance)` がある馬を優先する
- 騎手評価は `相手選び` と `接戦時の順位補正` に強く使う
- `pattern_kis` と矛盾する場合は過信しない

## 対象外

今回の実装では以下は対象外とする。

- 騎手の年間総合ランキングだけを保存する用途
- 騎手の全履歴DB化
- 厩舎や馬主など他ランキングとの同時対応
- 予想ロジックへの大幅な再学習処理

## 実装上の注意

### パラメータ正規化

- `course` は `kawasaki` などAPI側の正規値を採用
- `track_condition` は既存の馬場APIの表記と揃える
- `period` は固定列挙にする

### スクレイピング安定性

- 画面の並び順や列順に依存しすぎない
- ヘッダ文言で列判定する
- 数値は `%` や全角混在を正規化する

### 欠損時の扱い

- 条件に一致するデータがない場合は `items: []`
- 取得失敗とデータ0件を分けて返す

## テスト観点

### API

- 川崎、距離1400、良馬場で正常取得できる
- 馬場条件違いで件数または順位が変化する
- 表示期間違いで結果が変化する
- 0件時に例外にならない

### 予想利用

- 短距離戦で騎手評価補正が入る
- 馬の場・距離率が弱い馬を騎手だけで頭固定しない
- `pattern_kis` と同方向のときのみ加点が強くなる

## 予想スキルへの反映方針

`nankan-race-predictor` には以下の文脈で組み込む。

- 主材料: オッズ、勝ちパターン分析、馬場、馬体重
- 補助材料: 傾向、持ち時計、上がり時計、脚質、リーディングジョッキー

出力時は根拠欄で次のように表現する。

- `騎手の川崎1400m適性が上位`
- `当該馬場条件での騎手成績が安定`
- `短距離戦で騎手補正を加点`

## 実装優先順位

1. `GET /nankan/leading/jockeys` の追加
2. レスポンス正規化
3. 予想ロジックの補正レイヤー追加
4. 根拠文言への反映

## 完了条件

以下を満たしたら完了とする。

- APIで条件付きのリーディングジョッキー情報が返る
- 予想時に当該レース条件で騎手補正が使われる
- 根拠文言に騎手補正の説明が出る
- 騎手情報だけで本命固定しない制御が入っている
