# 010-南関東結果API追加実装仕様書

## 0. 最初に読む要約
- 対象機能: 南関東公式の単レース結果取得API
- 改修目的: 現在の `/nankan` 公式APIに、card/oddsと同じ粒度でresultを追加する。
- 現行仕様の要点:
  - `/nankan` は既に実装済みで、開催、出走表、オッズを返せる。
  - `/nankankeiba/pattern` は分析APIであり、結果APIではない。
  - `/nankan/.../result` は未実装。
- 実装時の最重要注意点:
  - 今回は南関公式結果APIだけを追加する。
  - 既存card/odds/patternの仕様を広げたり作り直したりしない。
  - 払戻 `bet_type` は英語canonicalへ正規化する。

## 1. 変更後仕様
- 入力:
  - `race_id`: 16桁南関race_id。例 `2026070419040501`
  - `date_`: `YYYY-MM-DD`
  - `course`: `urawa`, `funabashi`, `ohi`, `kawasaki`
  - `race_no`: 1から12
  - `refresh`: 任意。`true` の場合はcacheを使わず再取得する。
- 出力:
  - 既存 `RaceResult`。
  - `race_id`: 16桁南関race_id。
  - `race_name`: レース名。
  - `results`: `ResultEntry` の配列。
  - `payouts`: `PayoutEntry` の配列。
  - `source`: `https://www.nankankeiba.com/result/{race_id}.do`
  - `fetched_at`: 取得時刻。
  - `cache_hit`: cache利用時true。
- 追加endpoint:
  - `GET /nankan/races/{race_id}/result?refresh=false`
  - `GET /nankan/meetings/{date_}/{course}/races/{race_no}/result?refresh=false`
- 正常系:
  - `race_id` 指定で南関公式結果ページを取得し、着順と払戻を返す。
  - 日付・場・R指定では既存 `get_meeting` で `race_id` を解決してから結果を返す。
  - cache TTLは結果確定後データとして3600秒を既定にする。
- 異常系:
  - 16桁以外のrace_idは422。
  - 結果ページ404は404 `nankan result not available yet`。
  - 日付・場・Rからrace_idを解決できない場合は404。
  - 結果表がない場合は404 `nankan result table not found`。
  - 払戻表がない場合は結果だけ返すのではなく、初期実装では空 `payouts` を許容する。ただしwarningログを出す。
- 副作用:
  - 上流HTML取得。
  - TTLCacheまたはSQLiteTTLCacheへの保存。
  - 解析失敗時のログ出力。

## 9. 要確認事項

- 複勝の複数払戻行を、同一 `bet_type=place` の複数 `PayoutEntry` として返すことを確認する。
- 結果表が出た直後に払戻表だけ未反映の時間帯があるかは、開催中に実ページで確認する。
