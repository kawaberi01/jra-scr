# 020-major-venue-model 実装計画書

## 1. 対象と目的

- 対象: 東京05・中山06の主要場モデル。
- 目的: v89採否を決め、必要なら非衝突バージョンの正式版または2026年秋シャドー版を運用統合する。
- 対象外: V90ロジック変更、外部取得の無制限実行、実投票。

## 2. フェーズ

1. SQLiteと成果物を監査し、汚染台帳・未使用holdout・欠損を確定する。
2. as-of特徴量と評価器を監査・修正し、リーク防止テストを先に追加する。
3. baselineと事前登録候補をdevelopment/validationだけで比較し、holdout前に候補・閾値・採否基準を凍結する。
4. final holdoutを一度だけ評価し、正式採用/不採用/標本不足を決定する。
5. 採用版またはシャドー版をV理論、比較API、scout、predictor、保存へ必要最小限統合する。
6. ruff、diff check、対象/全pytest、API再起動、OpenAPI、代表レースを確認する。
7. 運用・昇格・ロールバック資料を完成し、チェックポイントcommit/push、main統合/pushを行う。

## 3. タスクとDoD

| ID | 作業 | DoD |
| --- | --- | --- |
| A1 | DB schema/期間/場/欠損/重複監査 | JSON/MDレポートが再生成可能 |
| A2 | 過去成果物の期間参照監査 | 汚染/未使用台帳がある |
| A3 | as-of監査 | 使用可否表と失敗するリークテストがある |
| E1 | 実験契約凍結 | 候補<=10/世代、<=3世代、基準がholdout前commit済み |

| I1 | 実装 | 出力契約・ルーティング・保存が後方互換 |

## 4. 完了判定

- 未使用holdout>=30買い目なら固定基準により採用または不採用。
- 未使用holdout不足なら正式採用と呼ばず、発走前保存・固定再評価数・昇格手順を備えたshadow運用を完成する。
