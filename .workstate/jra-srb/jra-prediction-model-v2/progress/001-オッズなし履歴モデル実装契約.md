# JRAオッズなし履歴モデル初版 実装契約

## 1. 対象
- 対象 root: `D:\develop\jra-scr`
- 対象機能: 既存JRA履歴DBからの正規化学習データ生成、1着/3着内確率モデル、時系列評価
- 改修目的: DBを変更せず、過去レースだけで再現可能な初版学習モデルを作る
- reference_status: 外部referenceなし。実DB・実コードを正とする
- 主入力: `020/030-JRA予想モデルV2`、ユーザーの「オッズ・時点データは取得不能」「DBを変えない」指定

## 2. 今回変更する範囲
- race_idから競馬場を派生し、芝/ダート・距離等を学習用レコードへ正規化する。
- 対象レースより前の結果だけから馬・騎手・調教師の履歴特徴量を構築する。
- 正規化データをDB外のgzip JSONLへ保存する。
- 1着と3着内を別々に学習し、係数をJSONモデルへ保存する。
- 開催日単位の時系列holdoutで順位・確率を評価する。

## 3. 今回変更しない範囲
- `analysis.sqlite`のschema・値・既存予想・評価。
- オッズ、Ω指数、当日途中傾向、発走時点データ。
- 現行ライブ予想APIへのモデル接続。
- Nankan関連。

## 4. 実装順序
1. DB読取・正規化・履歴特徴量生成。
2. gzip JSONL出力とデータ品質集計。
3. ロジスティック回帰2モデルの学習・JSON化。
4. 時系列holdout評価。
5. testと実DB実行。

## 6. テスト / 検証
- race_id→競馬場、距離・斤量・年齢の正規化。
- 同一レースの結果がそのレース自身の特徴量へ入らない。
- 開催日単位でtrain/validationが分離される。
- JSONモデルの推論値がscikit-learnと一致する。
- 実DBを読み取り専用で開き、件数・期間・評価値を成果物へ記録する。

## 7. 禁止事項
- DBのALTER/UPDATE/INSERT。
- 最終オッズ・人気・対象レース結果の特徴量利用。
- ランダム分割。
- validation結果を見た反復重み調整。

## 8. 実コード突合結果
- 一致: race_id、race_date、surface、distance、runner、resultが既存schemaにある。
- 矛盾: 仕様のオッズ・期待値はユーザー指定により対象外。学習開始閾値は既存約4,800Rを使うため満たす。
- 実コード優先: `course`は過去result由来行でコース説明になっているため、race_idの競馬場コードを正とする。

## 9. 新規抽象化の扱い
- datasetとmodelを分離する。正規化と学習依存を切り離し、DB不変・純粋関数testを可能にするため。
- Repository/DIは追加しない。
