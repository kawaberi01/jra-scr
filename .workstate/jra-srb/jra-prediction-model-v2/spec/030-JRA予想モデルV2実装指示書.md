# 030-JRA予想モデルV2実装指示書

> 2026-07-11 実装指示更新: 初版は `analysis.sqlite` を読取専用で使用し、正規化データ・モデルをDB外へ生成する。オッズ・人気・Ω指数・時点データを特徴量に入れず、既存DBのALTER/UPDATE/INSERTを禁止する。

## 1. 対象概要
- 対象機能: JRA予想モデルV2
- 改修目的: 現行固定加点を、正規化、品質、確率、期待値、見送り付きへ更新する
- 行う処理: bundleから特徴量を固定し、順位と購入判断を分離して保存・評価する
- 変更してよい範囲: JRA予想engine/models/API/analysis store/scripts/skills/tests/config
- 変更してはいけない範囲: Nankan予想、既存v1 record、取得済みDB、外部サイトの認証・公開範囲

## 2. 実装順序
1. 既存DBをバックアップし、v1評価を固定する。
2. 取得率・鮮度・組合せオッズを監査する。
3. 特徴量builderと品質判定を実装する。
4. rule-v2、confidence、no-betを実装する。
5. 買い目ポリシーを実装する。
6. v1/v2 shadow保存とwalk-forward評価を実装する。
7. APIとJRAスキルを更新する。
8. 将来データを蓄積し、学習版の採否を別判定する。

## 4. 実装ルール
- v1を削除・上書きしない。`theory_version`を分ける。
- 全特徴量は `value/status/source/as_of` を追跡可能にする。
- レース内正規化前の生値もsnapshotへ保存する。
- 市場特徴量を能力特徴量へ混ぜず、別スコアで保持する。
- 対象券種オッズがなければ期待値を推定せず、買い目0件とする。
- 結果確定後のデータを事前特徴量へ追加しない。
- config変更時はmodel_versionまたはconfig hashを必ず変える。
- 既存構成にないRepository/DI層を追加しない。

## 6. レビュー観点
- Ω指数のスケールが他特徴量を支配していないか。
- 市場追随と独自能力評価を混同していないか。
- 欠損を0や平均で黙って埋めていないか。
- 同日結果・確定オッズの先読みがないか。
- no-betがAPI、保存、スキル出力で一貫するか。
- 回収率だけでなくBrier、top1、axis top3、最大ドローダウンを確認しているか。
- セグメント別サンプル数が不足した評価を採用していないか。

## 7. 禁止事項
- 2026-07-11の16Rだけに合わせた重み最適化
- ランダムtrain/test分割
- 同一開催日の一部をtrain、一部をtestへ無作為分割
- 券種オッズなしでの期待値・払戻推定
- 会員限定データの自動取得
- v1評価データの破壊・上書き
- 「的中率改善」だけを理由に点数を無制限に増やすこと
