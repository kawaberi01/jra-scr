# 005-JRA予想モデルV2現行仕様整理

## 1. 現行フロー
1. `JraPredictionService` が出馬表、単勝、同日傾向、公開分析、近走lite指標を束ねる。
2. `build_prediction_record` が馬ごとの固定スコアを計算する。
3. スコア上位3頭を予想順位とし、1位軸のワイド2点を各500円で生成する。
4. `AnalysisSQLiteStore` が予想、買い目、結果、払戻、評価を保存する。

## 2. 現行スコア
- Ω指数: 生値をそのまま加点
- 市場支持: `30 / 単勝オッズ`
- 近走時計: `max(0, 8 - 順位)`
- 近走上がり: `max(0, 6 - 順位)`
- 全項目を同一スコアへ直線加算し、欠損は単に加点なしとする。

## 3. 実地評価
- 対象: 2026-07-11、発走前取得できた16R
- 買い目: 32点、総額16,000円
- 的中: 3R、3点
- 払戻: 8,150円
- 回収率: 50.94%
- 全36Rの結果・払戻、予想16Rの評価は保存済み。DB整合性は `ok`。

## 4. 現行の問題
- Ω指数が約80～100の生値で入り、他特徴量より構造的に支配的になる。
- 単勝人気を直接強く加点するため、能力評価と市場評価を分離できない。
- レース条件、データ充足率、スコア差を使った信頼度がない。
- ワイド組合せオッズが取れなくても定額2点を購入候補にする。
- 初勝負、新馬、2歳、短距離、ダート等のレース種別差を扱わない。
- 馬場状態や券種オッズの欠損が順位・購入可否へ明示的に反映されない。
- 予想確率がなく、校正、期待値、適正ベット額を評価できない。
- ルール変更をv1と並行比較するshadow運用がない。

## 5. 維持する既存資産
- 取得・キャッシュ・公開範囲制御
- `JraPredictionBundle`
- SQLiteの予想・買い目・結果・評価テーブル
- 取得時刻、未確定、欠損の状態管理
- JRA予想スキルの固定出力形式

## 6. 判断
- API取得基盤は作り直さない。
- V2はエンジン、特徴量スナップショット、評価集計、買い目ポリシーを差し替える。
- 機械学習は十分な事前データが集まるまで有効化せず、まず正規化ルールモデルをV2として実装する。
