# 030-JRA発走前ライブシャドー記録実装指示書

## 1. 対象概要

- 対象機能: JRA発走前ライブシャドー記録
- 改修目的: 発走前判断を後から完全に追跡できる観測として保存する。
- 変更してよい範囲: `models.py`、`jra_day_race_scout.py`、`analysis_store.py`、`app.py`、関連test、対象`.workstate`。
- 変更してはいけない範囲: 判断閾値、モデル係数、実購入処理、結果収集、既存snapshot一意制約、無関係なログ。

## 2. 実装順序

1. 観測modelとshadow正規化helperを追加する。
2. additive schema、transaction保存、一覧取得を追加する。
3. Scout成功経路から観測を組み立て、スカウト保存時に渡す。
4. race単位GET APIを追加する。
5. unit/store/API testを追加し、pytest・ruffを実行する。
6. 個別・共通進捗を更新する。

## 4. 実装ルール

- 保存用`decision`は元dictを破壊せず複製する。
- `source_status`に元の`status`を残し、保存用`status`と`ticket_status`は`shadow_only`、`tickets`は空にする。
- `observed_at`は保存した単勝オッズの`fetched_at`と一致させる。
- `observation_id`はrunとraceから決定的に生成する。
- 別runの同一race観測は削除・上書きしない。
- `race_id`を結果照合キーにするが、結果データは観測payloadへ混ぜない。
- 既存構成にないRepository/Service/DI層を追加しない。

## 6. レビュー観点

- 購入ticketが保存されないか。
- 観測時点より後の結果情報が入っていないか。
- model/policy版と完全な判断入力が残るか。
- 同一runの再保存と別runの追加保存が期待どおりか。
- 既存API応答に大きな観測payloadを追加していないか。

## 7. 禁止事項・停止条件

- 閾値調整、係数再学習、実購入への昇格をしない。
- 既存の未コミットログ・一時ファイルを変更しない。
- 仕様外のschema再設計や横断リファクタをしない。
- 実装中に既存Scoutからオッズ取得時刻を確定できないと判明した場合は停止して仕様へ戻る。
