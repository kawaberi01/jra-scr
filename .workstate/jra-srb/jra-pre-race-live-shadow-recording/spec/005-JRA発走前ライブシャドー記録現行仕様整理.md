# 005-JRA発走前ライブシャドー記録現行仕様整理

## 1. 実コードで確認した事実

- `JraDayRaceScout.run()`は、開催一覧から未発走レースだけを対象に予想bundle、公開材料順位、履歴モデル順位、単勝判断を生成する。
- 通常戦の`build_win_ev_decision()`は`status`と`ticket_status`を`shadow_only`にし、`tickets=[]`を返す。
- スカウト結果は`jra_scout_runs`と`jra_scout_entries`へ保存されるが、完全なオッズ、モデル版、両ランキング、判断全体は保存されない。
- `odds_snapshots`にはオッズ時系列が保存されるが、判断やモデル版との同一観測単位は存在しない。
- 確定結果は同じanalysis SQLiteへ`race_id`をキーとして保存できる。

## 2. 現行の入口と呼び出し経路

| 順序 | 入口・処理 | 根拠 |
| --- | --- | --- |
| 1 | `POST /jra/days/{date_}/race-scout` | `src/jra_srb/app.py:1180` |
| 2 | `JraDayRaceScout.run()` | `src/jra_srb/jra_day_race_scout.py:87` |
| 3 | `get_prediction_bundle()`でカード・単勝オッズ取得 | `src/jra_srb/jra_day_race_scout.py:133` |
| 4 | 履歴モデルと公開材料からランキング生成 | `src/jra_srb/jra_day_race_scout.py:137` |
| 5 | `build_win_betting_decision()`で判断生成 | `src/jra_srb/jra_day_race_scout.py:142` |
| 6 | `save_jra_scout_result()`で要約保存 | `src/jra_srb/analysis_store.py:430` |

## 3. 入出力・副作用

- 入力: 対象日、候補上限、refresh、並列数、履歴モデルartifact、analysis SQLite。
- 出力: `JraDayRaceScoutResult`。
- DB副作用: スカウトrunとentryのupsert。
- 外部通信: JRA/netkeiba/keibalab由来の開催・カード・オッズ取得。
- 設定: `JRA_SRB_ANALYSIS_DB_PATH`、`JRA_SRB_HISTORY_MODEL_PATH`。

## 4. 要件との差分

| 要件 | 現行 | 差分 |
| --- | --- | --- |
| 同一観測時点の候補とオッズ | 別々の要約・snapshot | 観測payloadが必要 |
| モデル版の保存 | artifactに存在 | スカウト保存に含まれない |
| 判断全体の保存 | value要約のみ | 完全なshadow判断が必要 |
| 後日照合 | `race_id`は存在 | 観測一覧の参照手段が必要 |
| 購入ticketを生成しない | 通常戦のみ保証 | 保存前に全戦shadow化が必要 |

## 5. 実コード優先で採用する判断

- 新しいcollectorは作らず、既存スカウトの成功処理を観測トリガーとして流用する。
- オッズの`fetched_at`を観測時刻とし、そのオッズから導出したランキング・判断を同じpayloadへ格納する。
- 既存snapshotの一意制約とは別に、シャドー観測をrun単位でappend-only保存する。
- `race_id`と時系列参照APIにより、保存済み確定結果との後日照合を可能にする。

## 6. 未確認・対象外

- 自動的な払戻・損益評価は本機能に含めない。
- 定刻スケジューラーの追加は含めない。
- append-only odds snapshot化は`JRA-NEXT-002`として別管理する。
