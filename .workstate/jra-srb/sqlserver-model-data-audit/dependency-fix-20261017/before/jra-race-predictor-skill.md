# JRA Race Predictor

南関 `nankan-race-predictor` の出力順と判断枠組みをJRA用に適合したスキルです。公開・匿名データだけを使い、取得不能項目は推測で埋めません。

ローカル API を使う前に [local-race-api-ready](../local-race-api-ready/SKILL.md) を実行する。同じ作業で準備済みなら再実行しない。失敗したら予想 API に進まず理由を報告する。

## 手順

1. 日付、場、レース番号、開催回、開催日を特定する。
2. モード未指定なら `総合買い目型` を既定とする。
3. 発走前は次を取得する。
   - `GET /jra/meetings/{date}/{course}/races/{race_no}/prediction-bundle?meeting_no=...&meeting_day=...&refresh=true`
   - 履歴モデルの成果物が利用可能なら、`GET /jra/meetings/{date}/{course}/races/{race_no}/model-comparison?meeting_no=...&meeting_day=...&refresh=true`
   - 買い目を検討する場合は、`GET /jra/meetings/{date}/{course}/races/{race_no}/betting-decision?meeting_no=...&meeting_day=...&budget=...&refresh=true` を使う。
4. 本線候補を決めた後、対象組合せの実オッズを個別に取得する。ワイドと馬連は本線-相手、三連複は本線-相手2頭について、`GET /meetings/{date}/{course}/races/{race_no}/odds?bet_type=...&combination=...&refresh=true` を使う。
5. `card`、`odds_summary`、`trend_context`、`public_analysis`、3種の lite 指標と、比較APIの二モデル・V系・総合評価を確認する。
6. `component_status` と取得日時を明記する。Umanity会員限定欄などは `unavailable` のまま扱う。
7. 頭候補、軸候補、相手候補を分け、順位と各馬の根拠を出す。V89対象場では `status=available` のV89順位を、過去走前提を満たせず `status=provisional` となった場合は暫定V89順位を評価軸にする。V90対象場では後述の `v90_official` を正式順位として使う。
8. V89対象場ではV89の正式買い目規則、V90対象場では後述の公式買い目規則を優先する。暫定V89は順位・軸・相手候補の比較だけに使い、買い目生成・期待値判定には使わない。APIの `shadow_only` は監査用の元判定として併記する。V系順位が `unavailable` の場合のみ、通常の `betting_decision` に従う。
9. 発走前の予想は、返答前に必ず analysis SQLite へ保存する。先に `jra-race-session-complete` の保存手順を読み、`prediction_id`、予想時点束、表示順位・印・軸・相手・買い目を保存して読み戻し検証する。保存に失敗した場合は `予想未保存` と明記し、結果取得・結果検証には進まない。
10. 確定後だけJRA結果・払戻を取得・保存し、保存済み予想を評価する。未確定なら評価しない。
11. 最終出力の末尾では `jra-dansou-keiba-reference` を使い、同スキルの `references/output-template.md` を読んだ断層競馬参考を付ける。本線の順位・買い目は断層参考で上書きしない。

## 二モデルの扱い

- 公開材料モデルは当日オッズ・公式情報・公開分析を使う。履歴モデルは対象日前日までの確定結果だけを使う。
- `top3_agreement` は強調材料にするが、二つの確率を合算した順位はまだ出さない。統合係数は別途シャドー評価で決める。
- 上位が食い違う場合は、馬番・両者の順位・履歴モデルの特徴量寄与を示し、当日情報またはオッズに理由があるか確認する。
- `history_model.status=unavailable` のときは公開材料モデルのみで予想し、履歴モデルの値を補完しない。
- 通常戦の単勝期待値判定は、履歴モデルのレース内正規化勝率と単勝オッズを比較する。

## 買い目の組み立て

- 標準では、単勝に加えて本線-相手のワイドを必ず検討対象にする。ワイドが未取得なら買い目に出さず、未取得と明記する。
- 馬連・三連複は、本線が公開材料と履歴モデルで支持され、相手も両者の上位または市場支持を得ている場合だけ検討する。新馬戦では、新馬専用戦略の本線と市場支持をこの条件に使う。
- 共同確率は未実装のため、馬連・三連複を「期待値あり」と断定しない。複数の独立材料による本線・相手の一致と、取得済み組合せオッズのバランスが取れる場合だけ「妙味候補」と表現する。
- 単勝、ワイド、馬連、三連複のいずれも、実オッズを取得できた組合せだけを出す。オッズ未取得の券種・組合せは推測で補わない。
- 買い目の各行に、券種、組合せ、オッズ、取得時点、採用理由、金額を必ず併記する。

## 新馬戦の買い目判定

- レース名に `新馬` または `メイクデビュー` を含む場合、`strategy=newcomer_public_market_consensus` を適用する。
- 新馬戦では履歴勝率による期待値判定を買い目根拠にしない。公開Ω指数1位かつ単勝支持3番人気以内の一致馬だけを単勝候補にする。
- 一致馬がいなければ `no_bet` とし、オッズだけを理由に大穴を自動提案しない。
- 一致馬がいる場合、その馬を予想順位1位・◎・軸候補として本線に置く。履歴モデル順位や大穴の期待値判定で本線を上書きしない。
- 出力では、新馬専用戦略であること、公開材料順位と市場順位を明記する。本線と買い目は同じ一致馬を指す。

## V系と総合評価の扱い

- `v_theory` は競馬場別に呼び分ける。東京・中山・京都・阪神は `v89`、札幌・函館・福島・新潟・小倉は `v90`、中京は対象外とする。
- 東京・中山・京都・阪神では、当面（仮運用期間中）もV89を正式な順位・軸・買い目判断のベースとして使う。APIや実装が `shadow` / `not_final` / `shadow_only` を返していても、それは検証・実装状態として別記し、V89正式運用を上書きしない。札幌・函館・福島・新潟・小倉ではV90を正式運用する。V90対象場で `status=available` かつ有効な出走馬順位がある場合は `v90_official` として扱い、APIの `application=summer_shadow` や `betting_status=rejected_for_purchase` は元データの状態として保存するが、正式運用を止める条件にはしない。
- V89が `status=provisional` の場合は、公開材料順位と履歴モデル順位を同じ順位尺度へ正規化した `v89_provisional_rank_v1` を表示順位・印・軸候補の評価軸にする。これは通常V89の過去走候補数の前提を満たせないレース向けの暫定値であり、V89正式買い目規則、V系チケット、確率・期待値の根拠には使わない。`ranking_sources` と `reason` を明記する。
- V90公式順位は、取消・除外馬を落として順位を詰め、1位を本命・頭・軸、2位以降を相手とする。公開材料・履歴モデル・当日傾向は根拠と注意点の補正に使い、V90順位自体を上書きしない。
- `total_evaluation` は確率合算ではないため、正式順位の代替にしない。V89対象場ではV89有効順位、V90対象場ではV90有効順位から正式な `predicted_ranking` と `predicted_top3` を保存する。
- 断層競馬参考は手順11に従い、予想本体の最後に必ず付ける。

## V90公式買い目

- 戦略名を `v90_official`、チケット方針を `v90_official_odds_filtered` とする。
- V90の有効順位1位を軸、2〜5位を相手候補とする。取消・除外馬は順位と全組合せから除く。
- 単勝は軸馬の実オッズが3.0〜10.9倍のときだけ採用する。
- ワイドは軸－相手2頭までとし、実オッズ下限3.0倍以上だけ採用する。
- 馬連は軸－相手2頭までとし、実オッズ6.0倍以上だけ採用する。
- 3連複は軸－相手2頭の組合せを最大3点とし、実オッズ5.0倍以上だけ採用する。
- 同じ組合せを複数券種で採用してよいが、取得不能オッズは推測しない。全券種が不採用なら `no_bet` とする。
- 既定予算は3000円とし、採用券へ100円単位で配分する。軸の単勝を採用できる場合は予算の30%、残りをワイド40%、馬連20%、3連複10%を目安に配分する。単勝不採用時はワイド50%、馬連30%、3連複20%を目安にし、券種内は本線ほど厚くする。
- 表示した金額付き買い目を `prediction_tickets` にそのまま保存する。`prediction_json.betting_decision_status` は `v90_official`、`raw_betting_decision_status` はAPIの元判定を保存する。
- オッズ帯は運用フィルターであり、校正済み期待値や利益保証とは表現しない。

## 評価の優先順

1. JRA公式の出馬表、馬場、馬体重、当日オッズ
2. Keibalab匿名公開のΩ指数・近5走
3. netkeiba匿名公開のコース分析
4. JRA公式の同日先行レース傾向
5. 近走から作る持ち時計・上がり・脚質 lite

公開外部データは補正材料です。JRA公式と矛盾するときはJRA公式を優先します。2歳戦・新馬戦では近走指標の比重を落とし、新馬戦の買い目は専用戦略に従います。

## 出力テンプレート

予想を出力する前に、必ず [references/output-template.md](references/output-template.md) を読み、見出し・順番・買い目の表記をそのまま使う。

## 状態ルール

- 発走前: `事前予想` と記録する。
- 結果が判明した後に初めて保存する場合は、`結果判明後の復元予想` と明記する。これを事前予想の保存記録や正式な購入評価と混同しない。
- 発走後に初めて作った順位は `回顧参考` とし、事前予想として評価しない。
- 結果0件、払戻0件、または確定表示が確認できない場合は `未確定` とする。
- 同日傾向は対象レースより前の確定レースだけを使う。
- キャッシュ再利用時は `cache_hit` を確認し、再観測を求められた場合だけ `refresh=true` を使う。

## モード

- `integrated_betting`: 総合買い目型（既定）
- `conservative`: 堅実型。複勝・ワイド・馬連寄り
- `value_focus`: 妙味重視型。公開評価と市場支持のずれを見る
- `aggressive_combo`: 攻め型。軸が明確な場合だけ三連系

`熱い！` は公式材料、市場支持、近走補正、相手の絞りやすさが複数一致するときだけ使います。

`買い方`、`予算別の買い方`、`マークシート向け` では、すべての買い目にオッズを併記します。
