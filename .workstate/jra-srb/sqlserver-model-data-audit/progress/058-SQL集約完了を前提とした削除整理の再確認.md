## 整理対象の区分

| 対象 | 判断・実削除時の条件 |
|---|---|
| 移行用ステージ、照合済み旧SQLiteの重複コピー | 整理対象にできる。固定版との対応、現用参照・writer停止、既存保管方針に基づくNAS保管/復旧資産の所在を対象ごとに確認。旧analysis/jobsを全コピー削除すると既存復元ツールの元DBを失うため、必要な一式を残す |
| 終了研究の大容量中間物・旧学習入力 | 結果・結論・条件・主要注意点・参照先を残し、終了用途の再実行をしない整理対象にできる。旧V系等を今後も実行するなら対象入力を保持する。全旧方式のSQL化は削除の一律条件にしない |
| 旧ログ・一時出力・非現用ビルド・再生成可能cache | 固有証跡と現用参照がないものを整理対象にする。JV-Link管理data/cacheの手動一括削除は今回認定していない |
| 最新研究成果・モデル・仕様・検証証跡 | 保持。`artifacts/jra_research/runs/20261022T080510Z_b6a4eb0716114496b680ea3378644159/`、J23追加6案/10案、前向き監査成果物、元R1、採用中モデルを旧入力コピー扱いで削除しない。SQL集約済みと同義ではない |
| 設定と現用コード | `data/storage/`、現行設定・コード・必要な呼出補助を保持。data/や.workstate/の一括削除は不可 |
| SQLのraw/history/market/ops、運用api_runtime | 現行共用データ・原本・来歴・通常保存を保持。集約完了を理由に削除しない |
| SQL内の旧移送原本・生成特徴の削減 | 033の候補は候補のまま。旧原本の包含・固有列と来歴、features_asofのreader依存を対象条件付きで確認してから判定。今回DELETE/TRUNCATE/DROP/SHRINKの実施可とは認定していない |
