# 元候補の固定版と推論入力互換性の照合

実施日: 2026-10-23 JST。068の次の着手点に対する利用者の「続けてください」に従い、元候補の版・購入条件・学習末尾・入力契約を照合した。研究用の参照構成を保存し、製品コード・本番設定は変更していない。

## 結論

**東京V110と東京・中山秋J23の保存版は特定でき、モデルSHA・学習末尾・主要ソースを照合できた。ただし、そのまま当日APIへ渡して運用できる状態ではない。**

新たな精度・利益の改善を測定した作業ではない。068の不一致見送り案は採用せず、元候補を独立した研究用参照構成として固定した。過去成績から選ばれた範囲であり、実用採用0・性能評価適格falseを維持する。

## 実際に確認したこと

V110の元reportに保存された8ソースは、現scriptsと元source複製の双方で全件SHA一致。J23の学習器・特徴ソース2件は元manifestと一致。J23の現live入口も現在のSHAを別途記録したが、後から作られた入口を元学習時のソースと称していない。

V110の保存最終モデルをSHA確認後に読み、42特徴名・固定政策・既定モデル・採用ゲートを照合。J23は既存load_frozenを使用し、2026-10-24の初期化、30月分の元履歴SHA、学習末尾と28係数の形状を確認した。SQL/APIへ接続せず完了した。

V110の保存済み2026-01-04入力3競走（202601040601/02/04、いずれも中山）を使い、result全体とT-10mを取り除く前後で全馬連の確率・期待倍率・買い目が完全一致。120/78/66ペア、確率最大差0、確率和正常。対象場の成績確認ではなく、入力契約だけの技術再生であり、最終モデルの学習内入力を使ったことも明記する。

J23の結果遮断推論は既存clean_record/scoreと068までの検証結果を再利用。今回、当日入力の生成や新しいJ23競走予測は実施していない。

## 利用前に埋める差

1. **V110の既定はV105。** `score_jra_second_ten.py`では`--trial V110`の明示が必要。通常入口は東京限定も保証しない。J23入口も東京・中山秋限定を強制しないため、参照構成側の範囲を別途守る必要がある。
2. **V110の入力は当日API本文と異なる。** レース属性・馬番号・斤量性齢/クラスを含む履歴特徴・当日0時のhistory_as_of・発表時刻付きT-30m単勝/馬連を備える既存学習JSON形式が必要。42特徴の順序一致を既存score_suiteが検査する。欠けた履歴や単勝をJ23特徴で代用できない。全馬連がなければV110はmissing_marketとなる。
3. **時刻の検査と公表時点の証明は別。** V110は発表時刻がT-30m以前か、履歴基準日が当日0時かを検査する。しかし旧保存の出馬表/発走時刻の真正性、各履歴の公表時点、締切前受領まで全て証明するものではない。旧protocolも歴史出馬表の大部分を未検証と記録している。J23 liveはこの種の未証明事項を理由にruntime_validation_onlyのまま。
4. **原型J23でも11月は補正政策の履歴依存で止まる。** 既存load_frozenは原型と一緒にQ03/Q06用の完全月次係数を構成する。11/1は`j23_missing_complete_prior_months`で拒否された。これは原型J23の推論式自体に月次購入精算が必要という意味ではなく、現入口の結合による制約。欠測10月を飛ばしたり、9月係数を11月へ流用したりしない。
5. **保存最終版と過去評価の版は違う。** V110の過去評価は各期間の学習版、J23は各月の再学習版。今回の固定最終版の将来成績は未検証。元の場/季節別ROIをそのまま固定版の実績として表示しない。V110の元candidate_gate_passedもfalseのまま保持した。
