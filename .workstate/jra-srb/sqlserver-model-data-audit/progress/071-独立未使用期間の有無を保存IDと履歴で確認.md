# 独立未使用期間の有無を保存IDと履歴で確認

実施日: 2026-10-23 JST。利用者は「使えると判定したのか」「何をすべきか」と問い直し、未使用の過去期間の有無を最初に調べる方針へ「着手してください」と指示した。これを現在の主作業とし、070/spec305の製品実装優先は撤回する。仕様は参考保管し、実装了承を再び求める段階ではない。

## 結論

**確認対象の保存データ・評価履歴では、今すぐ最終評価に使える、独立した未使用期間を確認できなかった。**

これは全世界の過去データに未使用が存在しないという証明ではない。確認済みの候補データ、保存予測、既存SQL監査の範囲で「未使用かつ十分な件数で、必要な入力が揃う」区間が見つからなかったという結論。モデルの実用採用0を維持する。

今行うべき次の工程は、今後の未閲覧対象レースへ向けて、候補版・比較対象・期間/件数・合否・結果前保存・途中変更禁止を決めること。未使用と証明できない13競走を採用テストへ流用したり、未評価の10月を自動的に未知と扱ったりしない。前向き検証の開始日は規則を固定し入力が受入可能になった後とし、2026-10-01まで遡って開始したことにしない。

## 照合した範囲と方法

- 元J23の30セル、7,127競走。2024-04-06〜2026-09-27の評価済み競走IDを抽出。元frozen.configの`retrospective_previously_seen_data=true`も確認。
- 元V110保存予測のtrial=V110、2,705競走。2024-04-06〜2026-09-13。2026/09の補助1競走も含む。
- 関連研究の保存predictions.jsonl.gzを18ファイル照合（V110自身も含み、空ファイル1件は評価0として記録）。競走IDが不明な行0。空ファイルの存在を「未使用レースが保存されている」と解釈しない。
- 現v1/v2の2026年races.jsonl.gzを読み、競走ID・日付・件数だけ集計。元manifestのファイルSHAと一致確認。結果・着順・払戻・確率を抽出/評価していない。
- 052/063/067/068の評価・条件選択履歴、057/065の既存10月入力監査を照合。今回SQL/HTTPの追加照会は0。

集計は日付とIDによる所在/使用履歴の調査。予測やROIの追加計算ではない。JSON本文の読込時に同居する結果フィールドへアクセスして値を評価しないようにした。

## 固定した候補版に対する時間順・対象場の確認

| 候補 | 固定版の学習末尾 | 学習後かつ対象範囲の保存競走 | 当該候補の評価履歴あり | 他の照合済み予測だけに存在 | 照合ファイルに評価IDが見つからない |
|---|---|---:|---:|---:|---:|
| J23 東京中山秋 | 2026-08-30 | 84 | 71 | 0 | 13 |
| V110 東京・夏除外 | 2026-09-13 | 0 | 0 | 0 | 0 |

これは2つの保存データ内の候補範囲であり、元J23の全評価対象や067の基準集合と母集団が違う。J23の71件を、最終固定モデルで未知評価した実績とも呼ばない。期間別再学習版の評価IDとの重なりを調べた値。

J23の未照合13件はすべて中山9月。9/5、6、12、13、19、20、22の競走で、IDはeligibility.jsonへ保存した。当該予測ファイルに見つからない理由や、別セッションで結果を参照したか、元入力条件が同じかは未証明。現在の学習末尾後だからという理由だけで未使用とはできない。

さらに、13競走で最大1点でも購入上限は13点。既存の最低100購入/30購入日/10的中を満たす採用検証には不足する。今回その13競走のモデル予測・購入精算はしていない。評価したくなっても先に未知性・入力条件を確認する必要がある。

## 期間別の扱い

- 2024-04〜2026-09の既評価区間: 候補選抜、誤差診断、場/季節別、2モデルの不一致見送りまで結果を使用済み。2026-04〜09を当初の「確認期」と呼んでいても、今の候補に対して未使用性は復活しない。
- それ以前の年: 固定モデルの学習末尾以前。今回の固定版を遡って使って独立な将来テストとはできない。別の学習時点へ戻す研究は新しい後ろ向き検証であり、未知性を自動回復させない。
- 2026年10月の終了済み開催: 候補の今回の再分析には含まれないが、研究全体/別予想での結果閲覧の有無は証明できていない。新しい未使用テストとして自動採用しない。
- 今後の開催: 規則を固定し、結果を見る前に予測・入力を保存できれば前向き検証の対象になり得る。現時点では開始済みではない。

## 10月の保存入力はどうか

057の既存SELECT監査では、固定31版の新しい10/3・4の48競走に対する時点市場/馬連払戻は0行。065の2026-10-23 UTC06:30時点の現receipt監査ではカード59/オッズ59/結果114競走だが、3種類のID交差0（東京20/20/56）。

この数値は既存の限定経路の確認を再利用したもので、別の原本やDBに必要なデータが絶対ないとは言わない。今回、最新SQL全体や別プロジェクトを再走査していない。新しい監査の目的で結果本文を開いて、未知性を自ら失わせることもしていない。

したがって「10月は完全な未使用過去テストとして、今すぐ計算できる」とは判定しない。10月分の探索再分析を行うこと自体とは区別するが、独立採用根拠とは称さない。

## 次の最初の作業

**前向き・実購入なしの採用検証条件を文書で固定する。** 候補は東京V110と東京中山秋J23の2つに限定し、新たな条件救済や混合はしない。固定版を使い続けるか、事前に決めた再学習規則を使うかも開始前に決める。比較対象、必要件数、評価時点、区間推定、2候補からの選択、途中変更/終了、入力欠測、結果前保存の受入条件を具体化する。

既存最低条件は設計の出発点であり、13件に合わせて緩めない。100購入あれば将来性能を保証できるという意味でもない。対象開催が少なければ検証は長期化し、2026年内に採用できるとは約束しない。

必要な保存処理の実装は、この検証契約が決まり、既存経路で何ができないか分かった後に範囲を決める。参照推論入口の完成を有効性判定に置き換えない。
