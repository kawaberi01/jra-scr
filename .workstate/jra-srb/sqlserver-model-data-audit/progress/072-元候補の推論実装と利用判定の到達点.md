独立未使用の過去区間が見つからないという071の結論は変わらない。これからのレース結果を、この作業中に存在するものとして作ることはできない。今回の技術再生を独立検証へ数えず、未達部分と理由を明記する。

## 実行と確認

最終コマンド:

```powershell
uv run --frozen --extra ml pytest -q tests/test_jra_research_original_candidate.py tests/test_score_jra_original_candidate.py tests/test_jra_research_j23_live.py
```

結果: **61 passed**。新規入力の馬ごとの特徴を変化させたfixtureでも元予測と全確率が一致。対象結果・払戻・T-10mの追加で出力不変。DB/HTTP/fitの禁止代替を置いて副作用がないことを確認。旧J23入口の関連回帰も成功。

初回のAST/テスト収集は、新規の入れ子辞書の閉じ括弧不足で失敗。修正してAST確認後に再実行し成功。その後、他場skipとxの行ラベル検査を自己レビューで追加し、その変更を含む最終61件が成功した。失敗を無視して配置したものではない。

joblib/NumPy2.5のarray.shapeに関するDeprecationWarningが1,057件出た。既存モデルの読み込み由来で、検証失敗ではない。今回、警告回避のためモデルを書き換えたり依存版を更新したりしていない。

実CLIもJ23/V110それぞれ正常終了。使ったのは馬名を持たない合成8頭の入力（generator=synthetic_test_fixture）。2026-11-01のIDは合成スキーマ例であり、実際の同日開催の取得/予想/実績ではない。CLI再生の入力・出力・SHA・テスト結果を下記成果物へ保存した。

## 前向き採用判定の固定内容

spec315と成果物prospective-protocol.json/protocol-lock.jsonへ記録。候補2方式の版/SHA/適用範囲・元政策を保持し、検証中の再学習/条件変更/混合は0。開始は規則固定後かつ入力受入可能後の未閲覧レースとする。

最初の判定は実際の適格開始から12暦月後。最低100購入/30購入日/10的中、ROI105%以上、2候補を考慮した日block bootstrapの片側97.5%下限100%超。件数不足は未判定とし、途中黒字で採用したり条件を緩めたりしない。市場M0のlogloss/Brier比較と収益比較は分ける。最大1/3払戻除外、日末DD、適用率/除外も報告する。

これは事前に固定した評価計画であり、成績が合格した記録ではない。100購入や12か月で十分な検出力があると証明したものでもなく、不確実なら未判定になる。年内利用を保証しない。

## 今後必要な外部事実

1. 新規開催の履歴/時計特徴が元学習と同じ意味・範囲で生成されること。旧liveの列名一致だけでは不十分。
2. 対象日前履歴、当時の完全出馬表、T-30m単勝/全馬連、締切前受領/予測保存の外部証跡。現runtime_validation_onlyは採用判定へ数えない。
3. その後に確定する未閲覧の公式結果/払戻を用いた、固定規則の独立評価。

これらは未実施・未確認。SQL/APIの当日接続や新規取得を完了済みと報告しない。まず入力同等性と事前保存の受入を完了し、以後の適格レースを蓄積する。利用者の確認不要という指示は継続し、承認質問を再開条件にしない。
