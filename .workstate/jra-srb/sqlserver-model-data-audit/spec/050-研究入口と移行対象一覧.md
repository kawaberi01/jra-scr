# 研究入口・置換profile・全体完了の台帳

作成日: 2026-10-15。既存scriptsの入口・関連呼出の限定調査。現時点でSQL置換profileは未実装。

## 1. 登録と互換性の原則

registryの1行は旧入口/研究族/必要capability/新CLIのprofile_id/feature contract/acceptance_test_id/状態/未達理由を持つ。下表は最低対象であり、実装M0で`scripts`と通常起動される`.workstate`補助だけを限定走査して呼出閉包を確定する。未分類を残した状態で全体完了にしない。

旧profileの名称・ロスター・特徴量・券種・目的変数・分割の意味を、新しいmasked profileで自動代用しない。SQLから旧入力を等価に構成できれば互換adapter、意味が変われば別profile_idとする。元研究の必要条件を満たさない場合はその族を未達に残す。旧入口の削除・拒否だけでは移行完了としない。

## 4. 再利用するもの・しないもの

市場の逆数正規化、純粋なモデルfit/predict、レース単位の数値処理は、引数と副作用を確認して再利用する。scriptsをimportしただけでfile/DBを開かないことをテストする。ファイルreader、manifestファイルhash、固定dataset path、writer、HTTP fetchを引き継がない。

API共有のstorage.py、jra_history_dataset.py、jra_recent_form_dataset.py、jra_history_model.pyは今回変更禁止。研究adapterに分離し、純粋計算の呼出で済む場合のみ利用。共有仕様の修正が必要なら具体的な変更契約をAPI側へ渡し、そのprofileをblockedで止める。

旧CLIの通常研究導線は新CLIへ文書で一本化する。既存scriptの入口変更が他作業と競合しないと確認できた時だけ、SQL研究への案内・旧入力の拒否を追加できる。単に隠す/拒否することをR01〜15の受入成功と数えない。

## 5. 境界と走査ルール

最終監査対象: `scripts/*.py`の学習/評価/検証/score/scout/build入口、そこから到達する研究用モジュール、直接呼ばれる`.workstate`補助。最初は`src/jra_srb/jra_*`を重点調査し、到達した内部/外部モジュールは名前によらず呼出閉包に含める。対象外はAPI運用collector、migration/restore、旧契約テスト、起動されない過去実行記録。除外には到達不能またはAPI運用専用の根拠と呼出元の証拠を付ける。

走査語: `sqlite3/duckdb/pyodbc/connect`、`read_races/read_csv/read_parquet/gzip.open`、`data/training/--db/--data-root/--race-json`、`httpx/requests`、`write_dataset/to_csv/to_parquet`。語があるだけで違反とせず、通常研究からの到達性を確認する。業務データをファイルへ保存する呼出、外部取得、SQL以外のDB接続を試験で禁止する。

状態はpending → implemented → verified。blocked_data（取得/履歴不足）、blocked_contract（列/単位/意味未確定）、blocked_concurrent（共有作業競合）を別記。blockedを対象外へ自動変更しない。M1と最終受入を別のstatusにする。

## 6. 最終完了条件

R01〜15およびM0で発見した同族入口・全variantが、SQL置換コマンド・入力契約・必要capability・受入証跡を持ちverifiedになること。SQLのみでモデル研究・score・評価を行え、旧DB接続0、研究元データ/全特徴量の永続複製0、未分類/未移行/必要capability不足0を確認する。

新しいmaskedモデルが動いても、旧研究の必要データや互換性が未解決なら全体未完了。全期間全種類の情報を新たに取得したことや、strict live再現を独立に証明したことは別の達成条件であり、今回の研究基盤完成から推定しない。
