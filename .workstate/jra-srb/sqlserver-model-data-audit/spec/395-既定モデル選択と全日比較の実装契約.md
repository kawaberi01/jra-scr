# 既定モデル選択と全日比較の実装契約

作成日: 2026-10-25。利用者の実装了承に基づく運用改修。spec390の並行研究は別作業として保持する。

## 選択・利用契約

- 正本は `configs/jra_prediction_models.json`。明示ID/別名を優先し、未指定だけ `default_model` を使う。
- ID、保存先、版、SHA、学習期間、利用可否、研究検証状態、既定承認、確率能力、購入承認を一か所で管理する。新しいファイルや番号の探索・自動昇格は禁止。
- 未検証・不採用・利用停止・未登録・成果物不一致は停止。別モデルへ自動代替しない。
- 初期既定は検算済みD0（spec365-v3）。model-manifest、assessment、independent-verification、実SHA・訓練ID範囲と研究記録を照合した。研究利用可・購入推奨不可。
- V89/V90は明示指定向け既存アダプターを保持。対象場・版・状態を照合して既存順位を使用する。新規購入について旧スキルの強制運用でshadow状態を承認へ変換しない。

## 推論・表示・保存契約

`scripts/jra_selected_model.py` がresolve/predict/scoutを提供し、個別予想と全日候補抽出が同じ選択処理を使う。既存の属性キメラ推論、公式取得、履歴準備、SQL Server Storeを再利用する。DBスキーマ・学習アルゴリズム・依存定義を変更しない。

live経路は公式カード再取得→単勝/全馬連実オッズ→既存履歴特徴準備→再度カード照合/オッズ取得→推論→本文/構造化値作成→新IDでSQL保存→Store/GET全文照合。不要な外部分析の取得へ依存しない。出走馬・競走条件が変われば停止する。古い保存束は元時刻を保ち、24時間超・未来時刻・学習期間違反は拒否する。24時間以内も直前最新とは限らず、履歴全場最新性・馬体重未発表を明記する。

馬連確率と2着内周辺確率だけを表示し、着順・単勝勝率に変換しない。順位・印・参考軸・相手は選択モデルに基づき、予想上位3着・頭候補は作らない。未実装券種確率・未取得実オッズ・未承認購入条件を補完しない。予算指定でも研究参考・購入0円。断層は別欄で単勝上位6人気・倍率・参考候補を保存し、本体や購入額へ混ぜない。

`prediction_json` にモデル情報、入力時点、順位の意味、印、参考軸/相手、頭候補の有無、購入0円、見送り理由、表示全文を保存する。最終本文を構造化値から生成し、表示だけの変更を拒否する。UUID付き新IDで保存し、旧予想を上書きしない。保存失敗・読戻し未確認時は結果へ進まない。結果確定後の既存結果保存・払戻評価へ接続し、着順非対応の指標は非適用として報告する。

評価JSONでは着順非対応のwinner/top3をnull/非適用とし、確率能力に合わせた馬連上位的中・実現ペア確率・2着内事実を別保存する。一意の1・2着を確認できない同着等は非適用。購入0円は未購入。既存DB列や旧モデルの評価は変更しない。

## 全日比較契約

公式全日一覧を保持し、同じ設定のモデルで比較する。初期指標は馬連最大予測確率による探索的相対比較。的中確度の校正・収益優位は未検証であり、頭数/人気集中の違いも残る。比較未対応モデルは停止し、従来の履歴勝率差へ戻さない。

初回取得は最大5件、以降はsnapshot indexまたは前回scout.jsonのentriesで成功入力を再利用し、残件を逐次補完する。元の観測時刻を保持し、未分析・発走済み・タイムアウトを全件残す。共通API接続不能では残りの取得を停止する。全日比較はローカル監査記録だけで、チケット・予想のSQL保存は行わない。

旧race-scout APIと旧rank_confidence.pyは従来履歴モデル専用として保持し、新しいスキル経路では共通既定の評価と混同しない。未取得の重賞格・S/V・gradeは補完しない。

## 既定更新手順

1. 新モデルと既存モデルの比較・検証・採否理由を案件内へ記録する。新規作成だけでは変更しない。
2. 対応する推論アダプターと確率能力を実装・確認し、モデル定義へ版/SHA/学習期間/利用状態/研究可否を登録する。
3. 研究参考としての既定承認と、購入推奨への承認を別々に判断する。未実装購入方針は購入0円のまま。
4. 検証に基づく更新決定後だけdefault_modelを変更する。旧モデル定義・成果物・予想を保持する。
5. resolve、明示優先、未検証拒否、利用不可停止、意味・表示保存一致、全日比較を検証し、進捗と次回メモへ記録する。
