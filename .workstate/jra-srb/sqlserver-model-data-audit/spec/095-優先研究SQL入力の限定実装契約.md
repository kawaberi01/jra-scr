# 優先研究SQL入力の限定実装契約

作成日: 2026-10-17。利用者承認済みの計画①〜③を対象とする。

- 対象: S06/S08共通のtrace履歴・pair v3入力経路、機械学習V91〜V111の共通入力差分の確認。
- 第一変更単位: `evaluate_chimera.load_history` のSQLite直接接続を研究専用SQL readerに置換。元の内容特徴の純計算は維持する。SQLの固定analysis版からnetkeiba3表を一意rowidで分割読取し、メモリ結合する。
- 再利用: `ResearchReader` の秘密設定・SET・timeout・例外抑制、`RunArtifacts` の実行記録。元データ・全特徴のファイル複製はしない。
- 制約: SQLはSELECTのみ。API/runtime.env/定期処理/schema/index/旧モデルを変更しない。SQLite/JSONL/HTTP/NASを研究入力の代替に使わない。
- 入力契約: source_key=analysis-current、snapshot=34のverified版。履歴期間2023-01-01〜2026-09-26は旧計算との接続確認用に維持し、増量する期間は④で明示変更する。馬名/推定生年/性別の旧対応は完全な馬ID同定ではない。
- 確認方法: 必要列・reader権限・一意snapshot/rowid索引、重複/孤児、行数上限・メモリ上限を確認。実SQLから履歴変換と観測件数を記録。計画③の承認範囲として限定実行を行い、全量移行検証や全研究再評価はしない。
- 停止条件: 必要列/版/権限/索引不足、重複、上限超過、SQL失敗。依存実行を止めて失敗runを保存し、根拠なく再実行しない。
- 完了区分: 履歴SQL化だけで③全体を完了としない。旧JSONL市場/カード/履歴特徴をSQL入力へ接続した学習・評価の一連実行が必要。既存のmasked特徴を完全な旧特徴と偽らない。
- 利用上限: ５時間枠の正確な残率取得手段は見つからない。取得できた上限通知/利用者からの残量連絡で、引継ぎ保存後に停止する。区切りごとに実行ID・状態・残件を保存し、監視できると断言しない。

## 第二変更単位：S06/S08の限定経路確認

- 入力日を実行前に固定: 学習2025-09-06/07、校正2025-10-04/05、評価2025-11-01/02。夏除外の旧方式に合わせる。既使用期間の動作確認で、成績比較や方式採否には使わない。
- 市場・ロスター・精算: verified source31の既存SQL表を索引経由で読取。O1/O2の時点・parser・全ペア・重複を確認し、正常結果とHR精算だけを評価に使う。
- 43履歴特徴: verified source34のR01履歴reader/純計算を再利用し、対象日より前の履歴で作る。現カードの属性はsource31のSE/RA保存JSONを使う。これは旧JSONLの履歴母集団や取得証明と同値ではない新しい研究用接続契約（analysis34-history-retrospective31-card-v1）。masked M1契約や旧モデルを上書きしない。
- 特徴の当時利用可能性と公開日訂正の完全再現は未証明。retrospective_research_onlyを明示する。旧JSONLやSQLiteからの補完はしない。
- 学習対象はS06(w_history)、S08に必要なq_history/q_recentとrecent_x変換だけ。v3の純学習・校正・scores/chooseを再利用し、旧main/旧成果物書込を呼ばない。
- 新runへモデル・条件・件数・評価・予測・hashのみ保存。保存モデルを再読込し、結果/払戻を渡さない入力で推論一致を確認する。限定日で通っても全期間の入力網羅やSQLite削除安全を保証しない。
