# 東京の秋開催を主対象とする再評価方針

優先順位更新: 利用者が2026年10月以降の実開催で試したいと明確化したため、[spec290](290-2026年10月以降の実開催試行方針.md)が着手順を上書きする。東京優先の意向は維持し、以下の過去再評価は補助資料とする。

作成日: 2026-10-23 JST。利用者「秋競馬は東京開催が多いのでこちらに用いたい」により、研究の主目的を**東京の秋開催で使える予測/購入判断の検証**へ具体化する。spec280の過去研究整理を引き継ぎ、別場の好成績を主な選択理由にしない。今回の実施は保存済み集計と対象ID/schemaの限定読取、方針更新のみ。新モデル/新政策性能計算・SQL/API・本番変更なし。

## 対象と優先順位

東京・秋は既存四季の定義を維持し、競馬場コード05かつ9〜11月。保存研究の該当対象は2024/2025とも10〜11月だった。実際の当年開催日程を今回照会したわけではなく、保存対象月と当年予定を混同しない。

1. **先行**: 同じ東京・秋の競走でJ23とR1/M0/J01の精度・校正・元購入の収益を比較する。市場M0は確率の対照であり購入モデルではない。J01はPL追加項を持たない構造上の対照だが、別々の学習係数も異なるので厳密な因果的除外試験とはしない。
2. **次段**: 機械学習V110の東京・秋を比較可能な対象/価格へ受入する。2000m超は旧研究からの補助条件として表示するが、先に東京の全対象を確認し、20競走をさらに場/距離/季節で細分化しない。
3. **次段**: S08対q_historyを東京の同じ内容観測条件で比較できるか確認する。観測/価格の受入不足なら性能計算を進めない。旧S08の全ペア/時点価格は分解runに保存されていない。
4. **参照枠**: V89の東京shadowやCatBoost/S06/S08の利用者指定試用は、券種・役割・学習末尾を分けて残す。V89の旧東京結果は5買い目でROI94%等の制約があり、東京向けという名称だけで優先採用しない。現運用は変更しない。

spec280の「福島/新潟見送り」は東京限定の比較では対象を変えないため、先行比較から外す。小倉/中山秋は研究上の追跡対象として保留し、東京へ好成績を転用しない。候補の数を膨らませるため旧A0〜A3と今回案を同時実行しない。

## 次の実行protocolに固定する内容

- 同じ東京競走、同じT30市場と払戻、各月以前の学習済みモデル/元保存OOSを用いる。後まで学習済みの最終モデルを2024/2025へ適用しない。
- J23/R1/J01は元の購入条件を維持し、同一競走上で見送りも含めて損益/適用数/校正を対応比較。元規則が違う比較はモデル＋政策の比較と表示する。
- 2024/2025は探索、2026東京秋の保存元不足を明記。単なる年再分割を未知評価とは呼ばない。
- 全東京秋を先行し、芝/ダート/距離の同時総当たりや、成績から良いレースだけを追加選択しない。
- 独立確認には当年以後の発走前入力/予測/価格の保存と後の公式結果が必要。057のSQL監査では新期間の完全束が未確認、058の現receiptはruntime_validation_only。今回再監査やSQL保存を開始したわけではない。
- Q03/Q06、確率混合、季節別の新学習は先行させない。東京での基礎比較とデータ受入を見てから別仕様で判断する。

## 次の最初の一手

**東京・秋のJ23/R1/M0/J01だけの実行protocolを固定し、既存保存行で対応比較する。** これが現在の優先であり、spec280旧A0〜A3の実行や血統/調教の監査を自動再開しない。将来の予測保存は既存250/058の時点受入契約に従い、完全入力の受入を性能運用と区別する。
