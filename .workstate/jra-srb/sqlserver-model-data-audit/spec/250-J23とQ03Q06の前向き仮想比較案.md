# J23・Q03・Q06の前向き仮想比較案

作成日: 2026-10-23 JST。状態: 利用者の「開始してください」により実装方針を承認済み。参考保存・発走後比較入口は実装済み、検証は[progress058](../progress/058-J23発走前参考保存の実装と検証.md)。前向き性能運用開始・再学習の完了を意味しない。

実装契約の具体化: 新CLIは保存済みSQL receiptを読む1競走入口とし、自動取得は既存収集経路の責務とする。現行receiptには公表時刻がなく、同一T30の証明もできないため、初期実装は動作検証区分として保存し、性能評価用の仮想賭金を0円とする。既存政策式による候補賭金は別欄に保持する。公表時刻を推測で補わない。月次入力が揃わない月は係数更新を拒否する。新機能の検証は合成入力・固定モデル・Store/receiptの代替を使い、実開催の完全入力がない状態で本番SQLへ架空予測を保存しない。

## 目的と監査上の制約

原型J23を基準とし、同じ予測・同じ元購入ペアにQ03/Q06の見送り条件を適用する。新しい確率モデル3本の比較ではない。既使用の2026-09以前を未知期間として使わず、開始宣言より後に発走前保存できた競走だけを前向き集合とする。

SQL限定監査はprogress/057、証跡は`artifacts/jra_research/j23_forward_audit_20261023/`。固定31版の2026-10-03/04の48競走は時点市場・馬連払戻行が0。API receiptではカード/オッズ59競走と結果137競走の交差が0。SQL内に独立した評価束が揃うことは確認できなかった。別の現行業務表やNAS全体の不存在は主張しない。

原型購入2,378競走のうち、parsed30版にO2区分3・4の観測が各1,592競走で存在。786競走は観測なし。区分だけで締切価格の意味・有効価格・原文一致を保証しない。Q03の現行係数は過去的中分限定のまま保持し、全対象価格モデルに変更しない。

## 固定する比較

- 原型: J23の全馬連確率から既存`select_pair`で最大1組を選択。オッズ4〜80、確率0.015以上、期待倍率1.05以上、仮想600円。選択・同点処理も既存式を再利用する。
- Q03: 元の選択ペアだけを対象に、`min(1,p×価格係数)×odds >= 1.05`なら600円、未達なら0円。オッズ帯は10未満/10以上30未満/30以上。
- Q06: 元の選択ペアだけを対象に、`min(1,p×直近3暦月の確率係数)×odds >= 1.05`なら600円、未達なら0円。
- 式・縮約・clipは`analyze_j23_ten_aspects.estimate/band/policy_stake`を変更せず再利用。月途中に更新しない。Q03/Q06で別ペアへ選び直さない。Q06の値は全ペア確率の再校正とは表示しない。
- 対照M0の全馬連市場確率も同じ入力から保存する。Q03/Q06は共通J23確率を用いるため、確率精度が改善したとは判定しない。

初期化候補は`initialization-candidate.json`に保存。2026-09までの元購入のみで計算した2026-10用Q03係数は順に0.9112394648435198、0.856875670703664、0.8301941936740923。Q06は2026-07〜09の173購入から1.0097754532760763。実運用開始月が変わる場合は、その前月までの完全な元J23仮想履歴で機械的に初期化し、欠測月を飛ばして「直近3月」を置き換えない。途中月開始なら当月分は次月更新まで使わない。

初回の候補モデルは既存`2026-09_J23.joblib`（学習末尾2026-08-30、7,697競走）。SHA256は`cc69d01c7b01776f30b5d55fa286fc0428eb58f41faecd72a7f32686f875034e`で実ファイルと照合済み。この固定モデルでまず入力/保存の成立を確認する案とする。元研究の月次再学習を再現した性能とは呼ばない。再学習は今回の実装対象外とし、必要なら学習期間・更新頻度を別途固定する。

## 発走前保存の成立条件

判断締切は検証済み発走時刻の30分前（T30）。受領・取得・公表時刻のうち必要なものが欠落、締切超過、単勝/馬連でcutoff相違、馬集合不一致、返還/発売停止/取消未解決なら予測を欠測理由付きで保存し、仮想購入しない。T10/T2をT30の代用にしない。

厳密な公表時刻を持たない通常APIオッズは既存receiptがあるだけでは十分としない。確認できる入力時点の水準を記録し、T30研究との同等性が証明できなければ動作検証枠に分ける。現在receiptのカードは`pre_race_card`だが、単勝/馬連の同一時点・全馬集合・結果までの完全性は未検証。

保存は判断締切以前に完了して再読込一致を確認する。保存完了時刻もSQL側時刻で保持できる既存経路を確認し、利用者が渡せるcreated_atだけを発走前証明にしない。既存Storeのupsertは不変ログではないため、prediction_idはrunごと一意、事前存在を拒否し、研究成果物とSQL保存内容のSHAを相互記録する。厳密な追記専用保証は現状未確認。

記録項目: API ID/統一ID/対応根拠、発走時刻と確認元、decision_cutoff、scored_at、saved_at、入力ごとの公表/取得/受領時刻とSHA、馬番号と全ペア順序、特徴量定義SHA/履歴末尾/モデルSHA、全馬連確率、元選択ペア・確率・価格、係数・訓練月、各政策の仮想金額/見送り理由。実馬番号を保存し、元研究のchosen整数だけを保存しない。

結果/締切価格は別の発走後成果物として追記し、事前予測を変更しない。全元購入ペアの締切価格を的中・外れによらず収集し、HR払戻とは別欄に保持する。返還・同着は既存精算契約を確認し、未解決を外れ0円にしない。

## 期間・評価・停止条件案

性能評価開始日は入力/保存の成立確認後、初回対象競走の前に宣言・保存する。初期動作検証の成績は本評価へ混ぜない。本評価は6暦月、共通有効1,000競走以上を基本とし、各政策100購入・30購入日・10的中未満は標本不足とする。件数不足でも結果を見て期間を延長せず、未達として終了する。

J23確率は同じ競走のM0とlogloss/Brierを比較。購入は政策ごとのROI、点数、的中数、購入日、利益、最大払戻除外ROI、ドローダウンを報告し、J23との差は同一開催日単位の対応bootstrap（固定seed、2,000回）で比較する。2政策の比較は各97.5%区間を用いる。実用化候補の必要条件案はROI105%以上、J23よりROI5ポイント以上、対応利益差の補正区間下端>0、最大払戻除外ROI100%以上、上記標本条件の全達成。条件を満たしても自動採用しない。

入力の対象数と欠測/理由を全件記録し、対象予定集合に対する成立率95%未満は品質ゲート不合格。入力訂正、モデル/係数SHA変化、未来結果依存、期限超過、SQL保存/再読込不一致があれば該当予測を失敗扱いとして依存処理を停止し、同じ失敗を自動再試行しない。利益による途中の閾値調整・政策選び直し・停止日変更は行わない。

## 実装前の了承対象と確認方法

了承対象は上記の1競走用J23 adapter、3政策の発走前参考保存、保存後照合、独立した発走後比較入口。API起動/取得は既存ready手順を利用し、日次タスク登録・自動実行・過去全件の再取得・再学習を含めない。

最小確認は、固定モデルの保存済み入力での推論一致、結果を混入させても推論不変、境界時刻と馬集合不一致の拒否、全ペア順序/元価格の照合、Q03/Q06の既存式一致と月境界、予測の重複/上書き拒否、SQL保存再読込と保存完了時刻、別保存結果の会計照合。

実装後の確認: 合成入力と実固定モデルの独立式照合、時点/馬集合/係数/保存代替/別run精算と回帰を含む41テストpassed。実SQLは既存receiptの3束の型・SHA・source・版を読取確認済み。元研究には全特徴入力の保存ファイルがなく、保存当時の実入力での推論再現には履歴再構築が必要なため未実施。実開催のSQL予測保存、commit後時刻の実測、全履歴を含む発走前運用は未実施。2026-11以降の完全な前月履歴の追加受入/係数更新運用も残る。詳細と証跡は058を正とする。
