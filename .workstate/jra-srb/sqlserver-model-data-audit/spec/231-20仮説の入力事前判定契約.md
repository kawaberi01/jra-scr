# 20仮説の入力事前判定契約

作成日: 2026-10-18 JST。spec230は利用者が実装・学習・性能測定まで承認済み。

- 対象は研究module/CLI/検証CLI/テスト/案件記録。既存API、スキル、R1、DBは変更しない。
- 最初に固定2025年原文を一巡し、正常平地8頭以上・着順一意の2025年1〜9月を抽出する。入力digestと全年正常競走数を既存監査に照合する。
- 各100競走以内で既存indexed_rowsによりsnapshot31のT30馬連・公表HRを読む。既存のSELECT権限・版・索引検査を再利用。別オッズ時点/版やSQLiteへ代替しない。
- 有効市場は一意・selected・jv-o1o2-v2・content hashあり・公表時刻がcutoff以下・全出走馬の全馬連が数値で揃うこと。cutoff/publicationはtimezoneを含む既存timestamp関数で検査する。
- HRは一意・hashあり・正の払戻・原文払戻と一致・正常結果の1/2着馬と一致を要求する。市場欠測・HR欠測・不正の理由を競走別に保存する。
- 一次（1〜6月）と二次（7〜9月）の双方で有効率95%以上を要求。いずれか未達なら学習前に停止し、全20案を未学習/未評価と明記する。入力不足を性能不合格と混同しない。
- 実装検証は小さい合成ケースで入力採否、境界95%、分割、全20ID、停止分岐、保存後の独立再集計を確認する。利用者は検証実行も含む作業を承認済み。
- 保存後検証はSQL再読取せず、競走別採否・月別集計・対象digest・成果物hash・学習実行数を再集計する。
- 事前判定を通過した場合にだけ、20特徴の厳密式と選抜/学習条件を追加固定して実装する。入力が不足している場合に未使用の学習器を大量に追加しない。
