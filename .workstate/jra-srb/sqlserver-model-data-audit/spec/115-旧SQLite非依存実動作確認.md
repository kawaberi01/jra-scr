# 旧SQLite非依存の実動作確認

作成日: 2026-10-17。利用者の「断言できるようにすすめてください」に基づき、spec110の実行未確認項目を検証する。

- 目的：現在運用するJ1〜J5/N1〜N3の8入口が旧SQLiteなしでSQLを使うことを確認する。既存API切替・研究SQL入力ガードの証跡も再利用する。
- 方法：存在しない互換パス、SQLite接続・旧DBファイルopen/existsの実行時拒否、別cwd、設定不足/SQL障害の拒否、保存済み判定あり/なし、同日最新scout選択、予想/結果/評価の保存と読戻し。
- SQL影響：UUID付き検証IDだけを使用。ドライバー接続の検証用leaseで全Store操作を1つの実SQL transactionへ参加させる。commit/closeを保留し、最後に実connectionをrollback/close。業務SQL、Store factory、型検証、SQL変換は本物を実行する。通常の操作別commitはこの試験では変更点であり、既存切替試験の証跡と区別する。
- SQL reader本来の接続・権限とbaselineは、lease適用前にも実接続で確認する。rollback後、別実接続で検証IDの残存0を確認する。
- 対象外：旧SQLite内容読取、原本の再走査、再取得・再移行、API再起動、設定変更、モデル変更、実レースの更新、データ削除。終了した旧研究の単発ツールは現用に含めない。
- 失敗時：依存する検証を中断し、例外型・段階・rollback状況を秘密を含めず記録する。原因を特定できた場合だけ対象限定で修正する。
- 完了判定：上記の実行結果、既存移行/研究/API証跡、対象範囲を明記して現用経路の非依存を判定する。全98ファイルの無条件削除可否とは分ける。
