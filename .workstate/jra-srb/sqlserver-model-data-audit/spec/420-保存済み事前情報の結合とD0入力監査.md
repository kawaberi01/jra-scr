# 保存済み事前情報の結合とD0入力監査

2026-10-25。利用者の継続指示と091の取得制約に従う調査契約。過去の不足履歴は取得できず、未来向け事前情報は既に保存されている。

対象は既存SQL Serverの受領記録・出馬表/オッズ版・予測・結果。2026-10-01〜25を限定SELECTし、受領UTC時刻の監査基準時点を固定する。上限は種類ごと5000行で、超えたら黙って切らず停止。既存Storeのreader接続のみを再利用。原本受領JSONを新研究runへ凍結し、以後はそのコピーから再集計可能にする。SQL/既定設定/予想/収集ジョブへの書込み、HTTP、新依存、新学習、過去の外部取得は対象外。

## 結合規則

- 同一race_idと時点ラベルについて、単勝と馬連それぞれの最初の受領版を選ぶ。結果・的中・払戻を選択に使わない。
- 出馬表は両オッズの観測時点以前に観測され、判定時点以前に受領した完全な事前版のうち最新を使う。結果ページから代用しない。
- 公式source/レースID/8〜18頭の平地/馬集合/正の実オッズ/時刻と受領が発走前かを確認。取消はカードで明示された馬だけに限定してオッズから取り除き、除外数を記録。時刻ラベルだけで実発走前と断定しない。
- 時点の間隔と鮮度は数値として併記し、今回の再現監査を旧spec415の合格へ昇格しない。時点不明・不足は理由付きで残す。
- 入力カタログに結果/順位/払戻を混入させず、結果sidecarとrace_idで結ぶ。結果未収録と事前情報欠落を区別する。
- 既存予測はprediction_id/race_id/理論版/作成時点と紐付け、発走前の作成時刻判定と、サーバー受領証拠を区別する。事後再計算を当時保存した予測とは呼ばない。

## D0入力

受領原本のofficial_recent_racesと表形式カードの違いを確認する。D0は6当日属性と市場のほか15履歴特徴とその状態/馬同定が必要。直近4走が保存されていても15列を同じ定義で復元できると仮定しない。保存済みD0予測にpublic_features/attributes/元市場が揃う場合は元モデルSHAを照合し、全確率を元D0と独立式で再計算して保存予測と比較する。足りない特徴はゼロ埋めしない。入力モデルが異なる案は別protocolとする。

## 成果と確認

新audit script/境界テスト、凍結受領JSONL.gz/入力カタログ/結果sidecar/予測別再現監査/日別集計/特徴対応表/報告。将来向け収集の有無、結合可能性、既存D0の再現、未知期間での性能を分ける。結果既知の保存分を前向き未知試験として報告しない。人工ケースで観測前カード選択・発走後拒否・取消/不足を確認し、凍結コピーから再集計とSHAを検証する。接続秘密は表示/出力しない。稼働中の収集へ介入しない。
