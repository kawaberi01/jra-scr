# キメラ初版の性能測定に必要な実装方針

作成日: 2026-10-18 JST。状態: 提示・承認した実装方針の記録。実装・学習・性能測定はprogress047で完了、性能不合格。

更新: 2026-10-18に利用者が本方針の実装・学習・性能測定を明示承認した。以降の具体的な固定契約はspec226、進捗はprogress047を正本とする。下記は承認前に提示した方針であり、再度の了承を求めない。

## 目的と前提

利用者依頼のデータ充足監査と新キメラの性能確認を分ける。データの存在率は予測性能ではない。spec220の構成は選定済みだが、学習済みモデル・予測・性能測定値はまだない。

利用者が提示した最新版AGENTS.mdの基本方針は「新規実装・仕様変更・構造変更を伴う作業では、実装前に方針・変更対象・既存機能の再利用方法を簡潔に提示し、利用者の了承を得てから実装してください」。そのため読取専用の監査を先行し、この具体案に対する了承後に研究モデルを実装する。構成の選定だけを実装方針の了承と扱わない。

## 実装する内容

- 新規研究モジュールsrc/jra_srb/jra_research_chimera.py：SDKに照合した時計/馬場条件の解析、同日結果を先取りしない能力・相手水準・適性・信頼度の特徴生成、固定3構成の学習・予測・集計。
- 新規CLI scripts/run_jra_chimera.py と scripts/verify_jra_chimera.py：一意runの保存、入力/モデル/予測hash、馬連確率合計、会計、合否の保存後照合。
- 意味のある少数テスト：時計の単位、時系列/同日漏洩、相手水準の過去限定、欠測時の縮約、目的確率の正規化、保存・読戻し一致。
- 変更範囲は新規研究経路と案件記録。既存のAPI・Store・当日予想・既定スキル・R1モデル・SQL schema/indexは変更しない。

学習器は馬連全組を正規化する対数損失と正則化を用いる小規模な構成を第一案とし、既存研究のscipyによる最適化・softmax検証を再利用する。人物の印やR1確率を教師にしない。可変頭数での馬連確率を正しく生成する経路を実装し、単勝/2頭間勝敗の単純な積を馬連確率へ読み替えない。基準時計などの推定も時系列限定で作り、全量fit後の過去再scoreを実績としない。

## 再利用する既存機能

- 年別RA/SE読取：AnnualReader / LiveAnnualReader、HistoryConfigの通常研究SQL接続と既存索引。
- 版・SHA・馬/競走ID：既存の検証規約とSDK定義。読取は固定snapshotを明記する。
- 成果物：RunArtifactsの一意run・予測ストリーム・hash・失敗記録。
- 市場と確定精算：既存T30市場の検証済み対象集合とHR公開払戻。旧SQLiteへ戻らない。
- 比較集計：既存の対数損失/Brier、日単位bootstrap、購入会計、保存後検証の仕組み。

## 固定する比較と期間

- 本体はA+B+Cの1案。Aのみ、A+Bの2対照を同一学習器・同一競走で比較する。アルゴリズム・価格閾値・券種の総当たりはしない。
- 履歴は収録済みの2003年以降を使う。学習用競走は原則2025-09-30以前、開発は前回と共通の2025年11〜12月485競走。2025年10月は既存校正期間として再使用を明記し、独立テストへ呼び替えない。
- 開発通過後のみ、既存T30基準と共通の2026年前期483競走・後期599競走・追加197競走を検証する。合計1279競走。収録済み履歴全体の件数と、市場/精算を伴う比較対象件数は分ける。
- これらの期間はすでに参照しているため探索的な過去比較。独立した採用判断は仕様凍結後の発走前保存を要する。
- 開発の採用率95%以上・400競走/15日以上、R1比対数損失0.5%以上改善・同時点市場比0.25%以上改善、日単位bootstrap2000回で2比較各97.5%区間が改善側、Brier悪化0.5%以内を全て必要とする。未達なら後続評価を実行しない。
- 後続は1000競走/40日以上・元対象採用率95%以上と同じ改善条件、各期間でR1に非悪化を必要とする。
- 購入は固定政策で別判定。100点/30購入日/10的中、ROI105%以上・R1比5ポイント改善、ROI95%下限100%超と対応利益差95%下限0円超を必要とする。標本不足は保留、条件探索を続けない。
- 全結果を保存し、最後の評価結果を見て本体を対照案へ選び直さない。旧R1系列終了の判断も変更しない。

## 実装前に確定する残項目

全期間監査の時計/馬場/ラップの欠測、初出走・履歴不足、末端の収録期限を受けて、縮約先・学習器の既定値・特徴定義を実行前の契約へ記録する。時計そのものを過去着順で代用しない。必要データが成立しなければ性能評価まで成功したとせず停止する。

この方針で実装・固定学習・保存後照合・予測精度と購入成績の別判定まで進めることを、次の承認対象とする。今回の監査スクリプトの実行結果はprogress046を参照する。
