# SQL研究CLIの利用手順

作成日: 2026-10-16。対象は `D:/develop/jra-scr` の研究用CLI。全研究族の移行状況は `../progress/002-進捗サマリ.md` と `configs/research/acceptance_registry.json` を参照する。

## R01：履歴・近走の分類モデル

研究接続はGit管理外の `data/storage/research.env` にある `JRA_SRB_RESEARCH_READER_CONNECTION_STRING` を使用する。接続先は既存 `jra_unified`、採用版は `analysis-current` snapshot34。APIのruntime.envを編集しない。現設定は2026-10-12までの保存済み公式結果を使う回顧研究であり、最新日まで更新済みという意味ではない。

```powershell
rtk uv run python scripts/run_jra_research.py history --config configs/research/history_sql_v1.json
rtk uv run python scripts/run_jra_research.py history --config configs/research/recent_form_sql_v2.json
rtk uv run python scripts/run_jra_research.py history-replay --run-id <学習run_id>
rtk uv run python scripts/run_jra_research.py history-score --config configs/research/history_sql_v1.json --model artifacts/jra_research/runs/<学習run_id>/model_history.json --race-id 202610120811
```

recent-formをscoreする時は `recent_form_sql_v2.json` と同profileのmodel_history.jsonを指定する。profile・特徴量順序/型・モデル/契約SHA不一致は拒否する。

出力は毎回新規の `artifacts/jra_research/runs/<run_id>/`。学習/replayは config・manifest・preflight・coverage・metrics・model_history のJSON6個、scoreは model/coverageを除く4個。元行、SQLite、全特徴量JSONLは出力しない。失敗時にはfailure.jsonを保存し、自動再試行しない。

両profileはwinとtop3の分類確率を出力する。履歴43特徴/近走49特徴、馬名キー、レース毎履歴更新を旧純計算と同じ意味で使う。レース日単位holdoutで評価した後、公開モデルは全量で再学習する。過去日を公開モデルでscoreした確率はholdout評価として扱わない。scoreでは対象結果/払戻と対象日以降の履歴を使わない。

R01の元入口 `scripts/train_jra_history_model.py` は金額を精算する購入研究ではない。R01のwin/top3ラベルを払戻額へ変換しない。共通精算の金額・複合券種受入はM2/各購入研究profileの条件として残る。

## 保存済み当日出馬表のスコア

`native-card-score` はSQL `api_runtime.write_receipts` の公式・完全な `pre_race_card` を使う。元のAPI IDを保持し、JV統一IDを生成しない。対象結果・払戻はSQLで除外する。履歴とモデルは対象日より前に限定し、固定snapshot34の2026-10-12までの保存履歴を使う。最新日までの履歴更新や、他19プロファイルの受入を意味しない。

今日の保存カードで、履歴・近走の両モデル各16頭の実スコアを確認した。次は再現用コマンドであり、開催済みレースの買い目ではない。

```powershell
rtk proxy uv run --frozen python scripts/run_jra_research.py native-card-score --config configs/research/history_sql_v1.json --model artifacts/jra_research/runs/20261016T004429Z_0ecb0d34e0974f75b006664944441e53/model_history.json --race-id 202610170404 --race-date 2026-10-17 --course niigata --race-no 4 --knowledge-cutoff "2026-10-17T11:20:00+09:00"
rtk proxy uv run --frozen python scripts/run_jra_research.py native-card-score --config configs/research/recent_form_sql_v2.json --model artifacts/jra_research/runs/20261016T004529Z_492339cfbc934c6a92bd60f814aa3fe7/model_history.json --race-id 202610170404 --race-date 2026-10-17 --course niigata --race-no 4 --knowledge-cutoff "2026-10-17T11:20:00+09:00"
```

明日2026-10-18は `--race-id` / `--race-date` / `--course` / `--race-no` を保存した出馬表の値へ変更し、`--knowledge-cutoff` に予想判断時点をtimezone付きで指定する。対象の公式出馬表がSQLへ保存されてから実行する。未保存・取得不完全・cutoff後のみ・同時刻異本文・モデル不一致は停止する。CLI自身は出馬表を取得しない。

`--source official`（既定）はHTTPSの `www.jra.go.jp` URLだけ採用する。明示公式URLを指定した場合はURL完全一致も要求する。出力はrun内metrics.jsonの各馬win/top3確率、manifestの入力digest・来歴。カード本文や特徴量は保存しない。オッズ・払戻・期待値・購入額はこの入口の出力対象ではない。

research-only / chunked_unproven / horse-name legacy history の制約を保持する。公開時点の完全性やstrict live replayを証明した入口とは扱わない。

## R01の監視付き再検証

通常は既存の受入runを確認する。実行経路を変更した時に、必要に応じて次のopt-in試験を使う。この試験は各profileで学習→replay→scoreを新規実行するため、結果確認だけで毎回実行しない。

```powershell
$env:JRA_RESEARCH_HISTORY_PURITY_SQL = '1'
rtk uv run pytest -q -s tests/test_jra_research_history_purity.py::test_actual_sql_history_training_replay_score_with_guards
Remove-Item Env:JRA_RESEARCH_HISTORY_PURITY_SQL
```

Pythonの既知DB/HTTP/file入口と新規runファイル集合・禁止payload形状を動的に監視し、数値replay一致を確認する。監視範囲は監査metricsに記録し、OS全体の監査とは称さない。
