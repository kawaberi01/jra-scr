# 030-南関東公式オッズAPI実装指示書

## 1. 対象概要
- 対象機能: 南関東公式オッズAPI
- 改修目的: 南関東4競馬場公式サイトから公式オッズを取得し、既存 `RaceOdds` 形式でAPI提供する
- この機能が行う処理:
  - 南関東公式HTMLをGET取得する
  - Shift_JISとしてdecodeする
  - 開催一覧、出走表、オッズ表をBeautifulSoupで解析する
  - `RaceOdds` / `OddsEntry` に変換する
  - FastAPIの `/nankan/...` endpointで返す
- 変更してよい範囲:
  - `src/jra_srb/app.py`
  - `src/jra_srb/models.py`
  - `src/jra_srb/normalization.py`
  - `src/jra_srb/nankan_*.py` 新規追加
  - `tests/test_nankan_*.py` 新規追加
  - `tests/fixtures/nankan_*.html` 新規追加
  - `docs/jra/05_API仕様.md`
- 変更してはいけない範囲:
  - 既存JRA公式APIのURL仕様
  - 既存netkeiba APIのURL仕様
  - `RaceOdds` / `OddsEntry` の既存フィールド意味
  - 既存テストfixtureの内容

## 2. 実装順序
1. fixtureを追加し、南関東HTML構造を固定する。
2. `NankanCourseCode` と南関東ID helperを追加する。
3. `nankan_provider.py` を追加し、HTML取得・decode・404変換を実装する。
4. `nankan_extractors.py` を追加し、開催一覧、出走表、券種別オッズを解析する。
5. `nankan_service.py` を追加し、cache、race_id解決、bet_type分岐、combination filterを実装する。
6. `app.py` にservice構築と `/nankan/...` endpointを追加する。
7. extractor/service/APIテストを追加する。
8. 既存テストを実行し、ドキュメントを更新する。

## 4. 実装ルール
- 既存構成にないDTO/Repository/DI分離を標準作成しない。
- `NankanService` / `NankanProvider` はnetkeibaの既存分離パターンに合わせて追加する。
- JRAの `CourseCode` へ南関東4場を追加しない。JRA course enumの意味が崩れるため。
- JRAの12桁 `RaceIdPath` を16桁対応へ広げない。既存endpointの契約が曖昧になるため。
- `odds_nin` は初期実装では使わない。
- `result`, `repay`, `race_trend` は初期実装では追加しない。
- 発売前404は上流障害として扱わず、未提供エラーにする。
- `−`, `－`, 空文字、`発売なし` は有効オッズとして返さない。
- 上流アクセスには既定1秒以上の間隔を設定できるようにする。

## 6. レビュー観点
- `/nankan` prefixで既存JRA/netkeiba APIから分離されているか。
- 16桁race_id validationが南関東endpointだけに閉じているか。
- `RaceOdds` の返し方が既存APIと同じか。
- HTML parserがテーブル順だけに過度依存せず、見出しやclassも併用しているか。
- 発売なし、未提供404、無効組み合わせを区別しているか。
- 外部通信のテストがfixture化されているか。
- 上流アクセス間隔が設定可能か。

## 7. 禁止事項
- 既存JRA `RaceIdPath` を16桁に変更しない。
- 既存 `CourseCode` に南関東4場を混ぜない。
- Playwrightやブラウザ実行を必須にしない。
- SPAT4投票やログインCookieを扱わない。
- 枠複/枠単を既存 `BetType` に無理に押し込まない。
- 実取得HTMLにない内部APIを推測で実装しない。
