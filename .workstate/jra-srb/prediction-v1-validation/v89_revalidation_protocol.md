# v89 再検証プロトコル

作成日: 2026-07-11

## 目的

`v89` を既知の holdout に合わせた候補のまま採用せず、未知の JRA 確定結果で再評価する。

## 凍結する理論

- theory version: `v89`
- 対象開催: 東京 (`05`)、中山 (`06`)、京都 (`08`)、阪神 (`09`)
- スコア・中穴オッズ帯・買い目点数・除外条件: `evaluate_v1_validation.py` の `THEORIES["v89"]` を変更しない。
- 中京およびその他の会場はこの評価の購入対象に含めない。

## 既知データとの境界

- 既知の holdout: `2026-01-01..2026-06-28`
- v89 はこの期間の結果を参照済みである。
- よって、この期間の v89 結果は参考値であり、正式採否の根拠に再利用しない。
- 新しい評価期間は `2026-06-29` 以後で、収集開始時点までに確定した JRA レースだけとする。

## 採否基準（評価実行前に固定）

最終判定は、以下をすべて満たした場合のみ `operating_candidate` とする。

1. 対象期間に v89 の買い目が30点以上ある。
2. ワイド回収率が 1.00 以上である。
3. 最大払戻1件を除いた回収率（no-max ROI）が 1.00 以上である。
4. 軸馬3着内率が 45% 以上である。
5. 最大払戻3件を除いた回収率を併記し、0.90未満なら高配当依存の要再検討とする。
6. 購入対象は主要4場に限り、後から会場・月・レースを追加除外しない。

買い目が30点未満の場合は、成績の良否にかかわらず `insufficient_sample` とする。理論の変更や正式採用は行わず、確定結果の蓄積を待つ。

## 実行手順

1. 新評価期間の JRA 出馬表・結果・払戻と netkeiba 結果対応を `data/db/analysis.sqlite` に保存する。
2. 収集後、JRA結果・払戻・対応表の件数を確認する。欠損レースは除外理由を記録する。
3. 次のコマンドで `v89` を一度だけ実行する。実行前に `--from-date` と `--to-date` を確定結果のある範囲に置き換える。

```powershell
rtk uv run python ".workstate/jra-srb/prediction-v1-validation/evaluate_v1_validation.py" --db "data/db/analysis.sqlite" --theory-version v89 --from-date 2026-06-29 --to-date YYYY-MM-DD --period-label v89_fresh_holdout --offline
```

4. 出力される `v89_fresh_holdout_summary.json`、`v89_fresh_holdout_report.md`、`v89_fresh_holdout_races.json` を保存する。
5. 上記の採否基準で判定し、このファイルとは別の決定メモに pass / fail / insufficient_sample を記録する。

## 禁止事項

- 新評価期間の結果を見てから v89 の条件を変更しない。
- 中京だけ、特定月だけ等の追加除外を導入しない。
- v89 の既知 holdout 結果を最終採用の証拠にしない。
- 発走後情報を予想入力へ混入させない。

## 分離して扱う枝

- `v86_local`: 主要4場以外を対象とする診断枝。v89の成績と合算しない。
- 中京: 当面は診断専用で、購入候補に戻さない。
