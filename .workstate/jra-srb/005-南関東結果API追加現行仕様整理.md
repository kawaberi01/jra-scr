# 005-南関東結果API追加現行仕様整理

## 1. 現在存在する南関API
- `src/jra_srb/app.py` には南関公式APIのtagとservice構築がある。
- `NankanRaceIdPath` は16桁race_idとして定義済み。
- `NankanService` は `get_meeting`, `get_race_card`, `get_race_card_by_number`, `get_race_odds`, `get_race_odds_by_number` を持つ。
- `NankanHttpProvider` は `fetch_meeting`, `fetch_calendar_month`, `fetch_race_card`, `fetch_odds` を持つ。
- `nankan_extractors.py` は開催一覧、出走表、オッズのparserを持つ。

## 2. 現在存在する南関endpoint
- `/nankan/meetings/{date_}/{course}`
- `/nankan/races/{race_id}/card`
- `/nankan/races/{race_id}/odds`
- `/nankan/meetings/{date_}/{course}/races/{race_no}/card`
- `/nankan/meetings/{date_}/{course}/races/{race_no}/odds`

## 3. 現在存在する南関関連endpoint
- `/nankankeiba/pattern/meetings/{date_}/{course}/races/{race_no}`
- これは勝ちパターン分析系であり、単レース結果取得ではない。

## 4. 現在存在しないもの
- `/nankan/races/{race_id}/result`
- `/nankan/meetings/{date_}/{course}/races/{race_no}/result`
- `NankanService.get_race_result`
- `NankanService.get_race_result_by_number`
- `NankanHttpProvider.fetch_result`
- `NankanFixtureProvider.fetch_result`
- `parse_nankan_race_result`
- `tests/fixtures/nankan_result_*.html`
- 南関公式結果APIのAPIテスト

## 5. 既存モデルと保存・精算側の状態
- `RaceResult` は既存にあり、`race_id`, `race_name`, `results`, `payouts`, `fetched_at`, `source`, `cache_hit` を持つ。
- `ResultEntry` は `rank`, `horse_no`, `horse_name`, `jockey`, `time` を持つ。
- `PayoutEntry` は `bet_type`, `combination`, `payout`, `popularity` を持つ。
- `AnalysisSQLiteStore.write_result` は16桁南関race_idでも保存できる。
- `AnalysisSQLiteStore.settle_bet_record` は `payouts` の `bet_type` と `combination` を使って実買い精算する。
- 払戻 `bet_type` は `win`, `place`, `quinella`, `wide`, `exacta`, `trio`, `trifecta` のcanonical値にしておくと、既存精算処理へそのまま接続できる。

## 6. 南関公式結果ページの既知URL
- 単レース結果:
  - `/result/{race_id}.do`
  - 例: `https://www.nankankeiba.com/result/2026070419040501.do`
- 開催全体払戻:
  - `/repay/{meeting_id}.do`
  - 今回のAPI追加対象外。単レース結果ページから結果と払戻を取る。

## 7. parser方針
- 結果着順:
  - 成績表から `着`, `馬番`, `馬名`, `騎手`, `タイム` を抽出する。
  - `ResultEntry` に存在しない枠、性齢、斤量、馬体重、着差、上がり、通過順は初期APIでは返さない。
- 払戻:
  - 単勝、複勝、普通馬複、ワイド、馬単、三連複、三連単を抽出する。
  - 枠複、枠単は既存 `BetType` と精算処理にないため初期APIでは対象外または解析しても保存対象外にする。
  - `普通馬複` は `quinella` に正規化する。
  - 組番は既存精算と合わせて `-` 区切りにする。
  - 複勝など複数払戻行がある券種は `PayoutEntry` を複数作る。

## 8. エラー方針
- 結果前や未来日で `/result/{race_id}.do` が404の場合は `nankan result not available yet` として404を返す。
- 結果ページはあるが結果表がない場合も、結果未提供として404扱いに寄せる。
- HTML構造変更で一部表だけ取れない場合は、結果表/払戻表のどちらが欠けたか分かるログを出す。
