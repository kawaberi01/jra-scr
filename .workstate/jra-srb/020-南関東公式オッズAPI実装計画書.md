# 020-南関東公式オッズAPI実装計画書

## 1. 対象と目的
- 対象機能: 南関東公式オッズ取得API
- 改修目的: 南関東4競馬場公式サイトのオッズHTMLを取得・解析し、既存 `RaceOdds` 形式で返す
- 今回の対象範囲:
  - 南関東開催一覧取得
  - 南関東出走表取得
  - 南関東オッズ取得
  - 単勝、複勝、馬複、ワイド、馬単、三連複、三連単
  - API endpoint追加
  - fixtureベースの自動テスト
- 今回やらないこと:
  - 枠複/枠単のAPI対応
  - 人気順専用API
  - レース傾向、結果、払戻のAPI対応
  - SPAT4や投票機能

## 2. 実装フェーズ
### Phase 1: 事前確認
- fixture取得対象URLを固定する。
- 16桁race_id、14桁meeting_id、場コード、券種ページコードをテストデータとして定義する。

### Phase 2: 既存変更単位の特定
- `models.py` に `NankanCourseCode` を追加する。
- `app.py` に `build_nankan_service`, `get_nankan_service`, `/nankan/...` endpointを追加する。
- 既存JRA endpointのpath validationは変更しない。

### Phase 3: 対象プロジェクトの既存パターンに沿った実装
- `nankan_provider.py` を追加する。
- `nankan_extractors.py` を追加する。
- `nankan_service.py` を追加する。
- 既存 `RaceOdds` / `OddsEntry` を返す。

### Phase 4: 入口 / 応答 / 設定
- `/nankan/meetings/{date_}/{course}`
- `/nankan/races/{race_id}/card`
- `/nankan/races/{race_id}/odds`
- `/nankan/meetings/{date_}/{course}/races/{race_no}/odds`
- 環境変数でmin intervalとconcurrencyを設定可能にする。

### Phase 5: テスト
- extractor単体テスト。
- service単体テスト。
- APIテスト。
- 既存テスト回帰。

### Phase 6: レビュー / 完了確認
- 仕様書の対象外を実装していないことを確認する。
- 上流アクセス間隔、404扱い、Shift_JIS decodeを確認する。

## 4. 完了判定
- 実装完了条件:
  - `/nankan/races/{race_id}/odds` が `RaceOdds` を返す。
  - `/nankan/meetings/{date}/{course}/races/{race_no}/odds` が開催一覧からrace_idを解決して返す。
  - 発売前404を未提供エラーとして返す。

- レビュー完了条件:

  - 上流への連続アクセス制御がある。
  - 発売なし、無効組み合わせ、未提供404の扱いがテストされている。
