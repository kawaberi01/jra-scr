### 入力

- 補助資料: 関連テスト、既存API仕様、analysis SQLiteと予想評価参照APIの既存spec

### 採用判断

- 保存済みSQLiteを読むGET API 2本とする。
- pathはStoreの主キーに合わせ`/jra/races/{race_id}/...`とする。
- snapshotの時点省略時は券種ごとの最新1件を返す。
- timelineの`bet_type`は必須、`combination`は任意とする。
- timelineは`fetched_at`昇順で返す。
- 結果系情報を一切返さない。
- DB変更、外部取得、MCP公開は対象外とする。

### 判断根拠

- 現行Storeはrace_idを主な検索キーとしている。
- 現行収集は`odds_timing`別に保存済み。
- 全券種・全時点・全組み合わせの無条件返却は応答が大きくなり得る。
- 既存MCPはallowlist公開であり、保存データAPIを自動公開する要件はない。
