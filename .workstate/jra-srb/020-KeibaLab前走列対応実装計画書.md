# 020-KeibaLab前走列対応実装計画書

## 1. 対象と目的
- 対象機能: KeibaLab 馬柱からの前走情報解析。
- 改修目的: 初出走馬の空欄を原因とする前走情報の誤紐付けを防ぐ。
- 今回の対象範囲: parser、fixture、parserテスト、予想束の手動回帰確認。
- 今回やらないこと: モデル再学習、DB再処理、予想ロジックの改変。

## 2. 実装フェーズ

### Phase 1: 事前確認
実HTMLの前走行について、馬番・馬名・空欄セル・前走セルの列順をfixtureへ固定する。

### Phase 2: 既存変更単位の特定
`parse_keibalab_umabashira` の前走行処理だけを変更単位とし、データモデルや service の責務を増やさない。

### Phase 3: 対象プロジェクトの既存パターンに沿った実装
前走セルの有無でフィルタせず、直接子 `td` の列位置により出走馬へ対応させる。

### Phase 4: 入口 / 表示 / 応答 / 設定
API契約は変更しない。既存の prediction-bundle が正しい `recent_races` と lite 指標を返すことを確認する。

### Phase 5: テスト
混在fixtureによるparserテストと、既存JRA予想関連テストを実行する。

### Phase 6: レビュー / 完了確認
初出走馬へ前走が入らず、後続馬が一列ずれないことをfixtureと実取得データで確認する。

## 4. 完了判定
- 実装完了条件: 前走の有無にかかわらず、各列が正しい馬へ対応する。
- テスト完了条件: 初出走混在fixtureのテストと既存関連テストが通る。
- レビュー完了条件: 空欄セルの除外・順序詰め・馬名による推測補完が残っていない。

## 5. 別タスク候補
- 既に誤った前走情報を含む予想束・保存済み予想の検出と再作成。
- KeibaLab HTML構造変更を早期検知する監査ジョブ。
