# 010-南関東公式オッズAPI実装仕様書

## 0. 最初に読む要約
- 対象機能: 南関東公式サイトからの開催一覧、出走表、オッズ取得API
- 改修目的: JRA公式オッズ取得と同様に、南関東地方競馬の公式オッズをAPIでリアルタイム相当取得する
- 現行仕様の要点:
  - 既存APIはFastAPI endpointからserviceを呼び、providerでHTMLを取得し、extractorで `RaceOdds` へ変換する。
  - netkeibaは `/netkeiba` prefixの独立serviceとして追加されている。
  - 共通レスポンスモデル `RaceOdds` / `OddsEntry` が既にある。
- 実装時の最重要注意点:
  - 南関東の `race_id` は16桁なので、12桁JRA endpointへ混ぜない。
  - 発売前404は取得失敗ではなく「オッズ未提供」として扱う。
  - オッズページはHTMLサーバー描画済みなので、GET再取得+HTMLパースを基本にする。

## 1. 変更後仕様
- 入力:
  - `date`: `YYYY-MM-DD`
  - `course`: `urawa`, `funabashi`, `ohi`, `kawasaki`
  - `race_no`: 1から12
  - `race_id`: 16桁。例 `2026070419040501`
  - `bet_type`: `win`, `place`, `quinella`, `wide`, `exacta`, `trio`, `trifecta`
  - `bet_types`: カンマ区切り複数券種
  - `combination`: カンマ区切り馬番。例 `5,7,6`
  - `refresh`: キャッシュを使わず再取得するフラグ
- 出力:
  - 既存 `RaceOdds` を返す。
  - 単一券種指定時は `bet_type` と `entries` を設定する。
  - 複数券種または未指定時は `odds` に券種ごとの `OddsEntry` 配列を設定する。
- 正常系:
  - `/nankan/races/{race_id}/odds` で南関東公式オッズを取得できる。
  - `/nankan/meetings/{date}/{course}` で開催一覧を取得できる。
  - `/nankan/meetings/{date}/{course}/races/{race_no}/odds` で日付・場・Rからオッズを取得できる。
  - `refresh=false` の場合は短TTLキャッシュを使う。
  - `refresh=true` の場合は上流を再取得する。
- 異常系:
  - 発売前などでオッズページが404の場合は `ResourceNotFoundError` 相当で `odds not available yet` を返す。
  - 未対応券種は `BadRequestError`。
  - 開催一覧に対象レースがない場合は404。
  - HTML構造が想定外で必要な表がない場合は上流解析エラーとして扱い、ログにsource URLと券種を残す。
- 副作用:
  - 上流HTML取得。
  - TTLCacheまたはSQLiteTTLCacheへのキャッシュ保存。
  - ログ出力。

## 2. 既存構成における担当
- 入口:
  - `src/jra_srb/app.py` に `/nankan/...` endpointを追加する。
- 入力モデル / DTO:
  - 既存 `RaceOdds`, `OddsEntry`, `RaceCard`, `MeetingSnapshot`, `MeetingRace` を優先流用する。
  - 南関東4場の `CourseCode` は既存JRA用 `CourseCode` と混ぜず、`NankanCourseCode` を追加する。

  - `httpx.AsyncClient` によるGET。
  - 403等で必要なら既存 `HttpProvider` と同様に `curl.exe` fallbackを検討する。
- 表示 / 応答:
  - FastAPIのJSONレスポンス。
  - 既存エラーハンドラに載る例外型を使う。
- 共通処理 / helper:
  - 既存 `TTLCache`, `SQLiteTTLCache`, `ProviderError`, `BadRequestError`, `ResourceNotFoundError` を使う。

## 5. エラー / ログ / 設定
- エラー処理:
  - 404: `ResourceNotFoundError("nankan odds not available yet: race_id=... bet_type=...")`
  - 未対応券種: `BadRequestError("unsupported nankan bet_type=...")`
  - HTML解析不能: `ProviderError` または専用例外を作らず既存例外に寄せる
- ログ:
  - service入口で `race_id`, `bet_type`, `bet_types`, `refresh` をinfoログに出す。
  - 解析失敗時はsource URLと対象selector/券種をwarningログに出す。
- 設定:
  - `JRA_SRB_NANKAN_MIN_INTERVAL_SECONDS`: 既定1.0秒
  - `JRA_SRB_NANKAN_MAX_CONCURRENCY`: 既定3
  - `JRA_SRB_CACHE_PATH`: 既存と同じ永続キャッシュを利用
- 機密情報の扱い:
  - ログイン、Cookie、SPAT4連携は扱わない。
  - 個人情報や購入情報は取得しない。

## 6. Reference との差分
| Reference 仮説 | 実コードの事実 | 採用判断 |
| --- | --- | --- |
| JRA公式取得へ南関東を追加する | netkeibaは独立service/prefixで追加されている | 南関東も独立service/prefixにする |
| JRAと同じ12桁race_idで扱う | 南関東は16桁 `meeting_id + race_no` | `NankanRaceIdPath` を別定義する |
| 内部JSON APIを探して使う | 実取得HTMLにオッズ表が含まれる | HTMLパースを採用する |
| 発売前は空配列で返す | 未来日のオッズURLは404 | 404は未提供エラーとして返す |
