## 2 取得したい単位

| 取得物 | 単位・必要範囲 | 用途 |
| --- | --- | --- |
| 対象カード | 1開催競走と、そのcutoff時点の全出走予定馬・取消等 | 今回の予想入力。結果の馬別成績表とは別 |
| 馬別履歴 | 対象カード全馬×対象日より前の全保存走 | 前走経路、間隔、条件変更、重賞実績等。近4走だけでは不足 |
| 同名競走の年次標本 | series_keyに対応する各editionの全出走馬、条件、馬別履歴、別領域の結果 | 該当して来なかった馬も含む分母と、年次検証 |
| 任意の追加観測 | 対象馬・開催場×種別×計測/評価/公表版 | プレ評価、体重、馬場。採用前は別データ |
| 充足と来歴 | 競走・馬・項目ごとの状態とrecord/証拠参照 | 未知、時点不明、履歴範囲、原本照合の説明 |

同名競走だけを履歴取得の対象にしない。例えば同名重賞の好走率を研究する場合も、各馬がそこへ来るまでの他のレースが必要。地方・海外・収録外について取得範囲と最終確認日を返す。保存内最終走と真の最新走を別に扱い、該当なしを網羅的な経験なしと呼ばない。

年度ごとの開催場・距離・番組を保持し、series_keyが同じでも京都と阪神を混同しない。馬の年度横断結合は確認済み恒久IDを使う。未対応の馬を馬名だけで自動統合しない。

| 現行の条件群 | 必要な原データ | 提案への回答 |
| --- | --- | --- |
| 基本属性 | 当該出馬表の年齢・性・枠・馬番・馬ID・出走状態 | participantsは対象同定に使える。別にcutoff時点の出馬表属性の版が必要 |
| 前哨戦経路 | 前走の競走名/series、格、斤量条件、競走記号 | race_conditionsのgradeは使える。weight_rule、競走記号/出走資格の原コードと定義版を追加または既存表から供給 |
| 直近成績と間隔 | 前走日、着順、異常/取消/失格等の状態 | runner_resultsとrace_editionsを結合。欠測着順を最下位へ置換しない |
| 条件変更 | 当該と前走の距離・斤量 | distance_mとcarried_weight_kg。現カードの斤量は結果表から遡及取得しない |
| 過去実績 | 同名/同場同距離の好走、GⅠ/GⅡ/GⅢの勝利/2〜3着 | 対象馬の全保存履歴に格と着順、条件の確認状態が必要。未同定/未確認格を非重賞扱いにしない |

### 優先して具体化する追加契約

1. **出馬表属性**: `runner_declarations`等の型付きレコード、または既存出馬表の版付き参照を再利用する。登録/出走予定/確定/取消・除外を区別し、枠・馬番・年齢・性・騎手・調教師・斤量・発走予定時刻を時点別に返す。participantsの現在値だけで過去カードを代用しない。これは表名の指定ではなく必要な取得内容。
2. **競走条件**: 斤量条件（定量/別定/ハンデ等）、出走資格・競走記号（牝馬限定等）、格付け体系/原コード/定義版。前走はGⅠ以外や一般競走もある。現行研究のRA原コードとの対応を固定し、単なる列名一致で結合しない。
3. **芝ダート・コース**: surfaceだけで現行track_codeを完全復元できるとは限らない。内外回り等のcourse_layout、原コード、開催場コードの名前空間を保持し、変換不能はunknown。無根拠な既定コードを埋めない。
4. **履歴の供給経路**: 案で後続扱いの近走履歴を早期に参照できると最新前走照合に有用。ただし近4走だけでは全保存実績を代替できない。既存研究履歴と公式カードの近走を対応付けて補完・不一致検出に使い、別の成績正本を無条件に作らない。

年齢は当該競走時点の値。騎手/調教師も恒久的な馬属性ではなく各出走時点の値とする。斤量条件と実際の負担重量は別項目。現在のv2は騎手・調教師の独自効果を使っておらず、取得できても自動追加しない。

## 4 成績・評価・文章の分離

案の切り分けは適切。次の意味を取得形式でも維持する。

- runner_resultsの馬別上りとrace_conditionsのレース上り、race_sectionalsの区間/累積を別に返す。時計の秒、距離m、斤量kg、数値精度を固定する。
- 着差は原文を維持し、前の馬との差/勝馬との差等の基準が判明すれば別の基準コードを返す。ハナ等を根拠なく秒へ変換しない。数値化する場合は原値と変換規則を残す。
- ratingsはpre_rating/race_performance/annual_race_rating、評価対象期間・距離区分・根拠競走・公表版を返す。当該結果の評価をプレ評価へ混ぜない。
- narrativesは原文、記者/発言者、対象馬、発言/編集記事/派生解釈を維持する。記述がない馬を「不利なし」と解釈しない。勝馬紹介だけで血統別好走率を集計しない。
- 確認済み文章は原文との照合済みという意味。記事の因果関係を実証済みとみなさない。文章タグのモデル採用は後続検証。
- 最終オッズは結果側のデータ。前日/当日途中のオッズを研究する際は観測時刻付き時系列が別途必要で、最終値で代用しない。

## 5 時点と版を指定する取得口

予測用の必須引数案は `target_edition_id, cutoff, availability_mode, snapshot_id, schema_version`。日時はタイムゾーン付き。snapshotは使用原本/正規化record/採用policy/ID対応版を再現可能に固定し、応答にmanifestとSHAを返す。物理的なDB全体複製は必要条件ではない。

- 案のlive_snapshotは当時取得した版、historical_verifiedは当時存在した内容と可用時点を証明した版を用いる。公表日だけで発走前と確定しない。
- **競走cutoffと研究用の採用版固定時点は別**。後日、昔の原文を人が正しく照合することはありうる。採用日時が昔の発走後だから一律除外するのでも、いま採用されたから当時利用可能とするのでもなく、元内容の可用性と研究snapshotの版を別々に判定する。
- 現在採用版の通常ビューは閲覧に有用だが、過去検証にはそのまま使わない。過去検証では各評価年のcutoffを個別に指定し、履歴の当該結果もcutoffまでに利用可能なものへ絞る。
- 現行モデルは保守的に対象日以前（同日除外）の履歴だけを使う。取得口の時刻精度が上がっても、この仕様を黙って変更しない。
- 対象レースの結果/回顧/事後評価は予測payloadに返さず、評価ラベル専用の取得経路へ分離する。過去レース結果も、その過去レースを予測する局面では入力へ入れない。
- 時点証拠がない資料はcoverageに理由付きで残し、厳密な事前payloadには入れない。既存の後ろ向き研究データは時点保証済みへ格上げしない。

## 6 欠測・未確認・不一致の返し方

案の値取得/検証/公開の3軸をそのまま返す。値は型付きNULLとし、空文字や0へ寄せない。追加でidentity_status、availability_status、履歴のcoverageを区別する。

応答例（field metadataの例でありDDLではない）:

```json
{
  "field": "pre_rating",
  "value": null,
  "value_state": "not_published",
  "review_state": "accepted",
  "publication_state": "adopted",
  "missing_reason": "source_has_no_value",
  "availability_status": "eligible",
  "record_id": "...",
  "evidence_refs": ["..."]
}
```

未確認や不一致の候補値は通常の値へ混ぜず、理由と参照だけを返す。調査待ち一覧は別取得にする。任意項目の欠測で全馬を黙って除外しない。案どおり未確認列をNULLにした公開版を作り、全出走馬の分母を保持する。

予想側の停止条件（馬ID/全頭集合/枠/斤量/時点等の必須入力不成立）と、任意パーツをunknownで処理する条件は予想側で定義する。資料の採用と、モデルへの特徴採用を分離する。返却件数の制限・打切り・ページ欠落をcoverageに出し、完全取得と誤認させない。

## 7 まとめて取得する形式

初期は既存SQL Server readerで参照できるビュー/パラメーター付き取得処理を優先し、API新設は必須にしない。通常ビュー単体ではcutoffを強制できないため、予測用の取得処理側で対象と時点条件を検査する。

論理的には以下の一括パッケージを返す。物理的に1本の巨大JOINにする必要はない。馬ごとの問い合わせやラップ×文章のJOINによる馬行重複を避ける。

```text
request: target_edition_id / cutoff / availability_mode / snapshot_id / schema_version
response:
  manifest       使用版、抽出/対応/採用規則、対象、cutoff、SHA
  race           当該競走の事前条件と発走予定時刻
  runners[]      当該時点の全対象馬、ID対応、出走状態、属性
  histories[]    馬ID×過去edition、成績・条件（cutoff検査済み）
  observations[] 任意の評価・計量・馬場（kindと時点別）
  availability[] 欠測、履歴範囲、対応未確定、時点不足、打切り
  provenance[]   record/field→証拠参照（原文全文は通常省略）
```

学習/評価用の過去年標本は別要求で同名seriesと年範囲を指定する。特徴用の年別カード・履歴パッケージと、`labels`（当該結果）を分離し、各年のcutoffで作る。元の正規化値を提供し、「過去GⅠ勝利あり」等の派生特徴は予想側が計算・版管理する。

現在のpredict CLIは限定されたキー/コードのv1入力を検査する。上の応答をそのまま渡せるわけではない。変換アダプターとv2事前適用機能は今後の実装であり、凍結済み研究v2の係数を今回変更しない。

## 8 優先順位と受入例

1. **既存パーツを揃える**: ID対応、全頭カード、斤量条件/競走記号、対象馬の他競走を含む履歴、時点/充足。取得側の段階1と既存履歴を連携する。
2. **追加候補を一つずつ試す**: 前走着差、事前プレレーティング。正規化後にカバレッジ・利用時点を監査し、v2固定基準との比較を先に定義する。取得成功だけで精度向上と判断しない。
3. **後続**: ラップ、通過、馬場測定、体重、文章タグ。保存は先行してよいが、全ての正規化完成を待って主軸研究を止めない。

取得側への受入条件案:

- 2024/2025の確認済み全馬成績を、既存研究IDへ重複なしで対応できる。1馬の旧採用版/現在版と根拠へ戻れる。
- 時点付きカード標本で登録馬と実出走馬、取消前後を区別できる。結果表から遡及したカードはそう表示される。
- 任意列の欠測を残して全馬を返せる。未対応馬や取得打切りが件数と理由で分かる。
- 同一snapshot/引数で使用record集合とSHAを再現できる。後日の公式訂正・再抽出で既存検証が無言で変わらない。
- 各年の事前取得へ当該結果・回顧・事後評価、cutoff後の版、時点不明値が入らない。後からの確認時刻と原文公表時刻を取り違えない。

上記は合意候補であり、取得側の実装完了・受入試験成功を報告するものではない。
