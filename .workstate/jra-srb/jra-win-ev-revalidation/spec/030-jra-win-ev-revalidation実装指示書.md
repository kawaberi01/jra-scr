# 030-jra-win-ev-revalidation 実装指示書

## 1. 対象概要

- 対象機能: JRA通常戦単勝EV再検証
- 改修目的: 未校正の順位値を購入勝率として扱う経路を止め、検証済み方策だけを昇格可能にする。
- 変更してよい範囲: 単勝EV判定、履歴モデル評価・校正用処理、再検証スクリプト、関連API応答、テスト、当Featureのprogress。
- 変更してはいけない範囲: 新馬戦方策、複数馬券種、V系、既存DBスキーマ、自動購入、無関係なリファクタ。

## 2. 実装前の必須確認

1. `progress/006-次回着手メモ.md` と `progress/002-進捗サマリ.md` を読む。
2. 本書、`020`、`010`、`005`、`000` の順で契約を確認する。
3. `git status --short` と対象ファイル差分を確認し、ユーザーの未コミット変更を保持する。
4. 履歴DBの単勝オッズ・結果取得率を読み取り専用で監査する。
5. 取得率95%未満または外部対象500R未満なら、実装を拡大せずデータ不足として停止する。

## 3. 実装順序

1. 通常戦EV応答を `shadow_only` にし、購入ticketsを空にする。
2. データ監査と固定時系列分割を実装する。
3. リークのない再学習・再推論データを生成する。
4. Platt / isotonic / 生値 / 市場ベースラインを比較する。
5. 固定グリッドを校正・方策選択期間だけで評価する。
6. 方策を1件に固定してから外部評価を1回実行する。
7. 採否レポートとprogressを更新する。
8. 外部評価合格時だけライブシャドーへ進む。

## 5. 実装ルール

- 確率名を省略せず、生値・レース内正規化・校正値・市場値を区別する。
- 外部評価行を学習、校正、方策選択へ使わない。
- グリッド値は`010`記載値だけを使い、結果を見て追加しない。
- 全候補は一律100円で比較する。
- ROIだけで候補を選ばず、`010`の辞書順をそのまま実装する。
- 外部評価は固定policy 1件に対して1回だけ行う。
- 大穴関連指標と払戻除外指標を省略しない。
- 外部評価不合格時に基準を下げない。
- 自動昇格、自動購入を実装しない。
- 新規DTO / Repository / Service / DI分離を理由なく追加しない。

## 6. テスト・レビュー観点

- データリーク0件を機械検証できること。
- split境界、dataset hash、artifact hash、policy versionが成果物に残ること。
- 市場ベースラインとの比較が必ず出ること。
- 各オッズ帯のサンプル数不足が明示されること。
- 単勝30倍超・50倍超採用率が正しいこと。
- 最大払戻除外、上位3払戻除外、払戻占有率が正しいこと。
- shadow状態では予算があってもticketsが空であること。
- 新馬戦の公開材料・市場一致方策が変わらないこと。
- 同じ入力で同じ固定policyとレポートを再生成できること。

## 7. 実行制約

- 実装中に本番反映、コミット、push、デプロイをしない。
- 大容量ログ・JSONを全文表示しない。
- source DBへ書き込まない。読み取り専用で開く。
- 外部評価結果を見た自動再探索ループを実行しない。
- テストや長時間評価は、対象・所要時間・出力先を明示してから実行する。

## 8. 停止条件

- 履歴オッズまたは結果の品質が基準未満。
- 既存変更と競合し、意図を保持できない。
- 必須指標を既存データから算出できない。
- 外部評価前に方策を一意に固定できない。
- DBスキーマ変更や外部データ購入など、今回の権限・範囲を超える対応が必要。
