# 020-jra-win-ev-revalidation 実装計画書

## 1. 対象と目的

- 対象機能: JRA通常戦単勝EV方策
- 目的: 未校正確率による大穴偏重を防ぎ、再現可能な時系列検証で採否を決める。
- 対象範囲: shadow化、データ監査、確率校正比較、方策グリッド、外部評価、ライブシャドー、採用判定。
- 対象外: 複数馬券種、新馬戦、V系、自動購入、資金最適化。

## 2. 実装フェーズ

### Phase 1: 安全化とデータ監査

- 通常戦EV方策を `shadow_only` に固定する。
- 履歴結果・単勝オッズ・特徴量の期間と取得率を監査する。
- 除外ルールと時系列境界を固定する。

### Phase 2: リークのない再推論

- 学習70%だけで履歴モデルを再学習する。
- 校正15%、外部15%を同一日非分割で固定する。
- 生確率、レース内正規化値、市場確率を保存する。

### Phase 3: 確率校正

- Plattとisotonicを校正期間だけで学習する。
- 全体・オッズ帯別のBrier、log loss、ECEを市場ベースラインと比較する。
- 購入方策に利用可能な確率方式を限定する。

### Phase 4: 方策選択

- 仕様で固定したグリッドだけを校正・方策選択期間で評価する。
- 大穴依存・払戻集中・ドローダウンを含む辞書順で候補を1つに固定する。

### Phase 5: 外部評価

- 固定方策を未使用15%へ1回だけ適用する。
- 昇格条件を機械判定し、採用・不採用レポートを作る。
- 不合格なら `shadow_only` を維持して終了する。

### Phase 6: ライブシャドー

- 外部評価合格時のみ開始する。
- 発走前候補を30開催日かつ200候補以上保存・評価する。
- 最終採用判定を人間が確認できる文書にする。

## 4. テスト計画

- 時系列分割で同一日が複数区間に入らない。
- 対象日以後の履歴を特徴量へ使わない。
- calibration fitに外部評価行が入らない。
- グリッドが仕様外の値を生成しない。
- 同率時も辞書順で方策が一意に決まる。
- 大穴関連指標、払戻除外指標、ドローダウンが既知データで正しい。
- 候補数不足や必須指標欠損で不採用になる。
- shadow状態ではAPIが購入ticketsを返さない。
- 新馬戦方策に影響しない。

## 5. 完了判定

- 実装完了: EVR-01～EVR-09が完了し、外部評価の採否が文書化されている。
- テスト完了: 新規単体テストと既存JRA予測・APIテストが成功している。
- 運用完了: 外部評価不合格ならshadow維持、合格ならライブシャドー開始条件が保存されている。
- 昇格完了: EVR-10～11を満たした場合のみ別途明示判断する。
