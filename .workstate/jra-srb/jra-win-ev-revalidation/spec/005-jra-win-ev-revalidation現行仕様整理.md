# 005-jra-win-ev-revalidation 現行仕様整理

## 1. 現行処理

1. 履歴モデルが各馬の `win_probability` を算出する。
2. 同一レースの生確率合計で割り、`win_probability_race_normalized` を作る。
3. 単勝オッズの逆数をレース内で正規化し、`market_probability` を作る。
4. `model_probability × win_odds` を期待回収倍率とする。
5. 次の全条件を満たす馬を候補にする。
   - 単勝2.0倍以上
   - 期待回収倍率1.05以上
   - モデル確率と市場確率の差0.03以上
6. 候補中の期待回収倍率が最大の馬へ予算全額を割り当てる。

## 2. 現行入出力

- 入力: 履歴モデル順位、単勝オッズ、予算
- 出力: `recommended` / `no_bet` / `unavailable`、選択馬、候補一覧、単勝1点
- 副作用: API単体はなし。呼び出し元によって予想保存・スカウト順位付けに利用される。

## 3. 現行検証

- 履歴モデル: 日付順holdoutでrunner-level Brier、log loss、ROC-AUC、race-level順位指標を計測済み。
- 単勝EV: 人工入力による閾値通過、no-bet、オッズ欠損の単体テストのみ。
- 未実施:
  - レース内正規化確率の校正評価
  - 市場確率ベースラインとの比較
  - オッズ帯・人気帯別のBrier / log loss / ECE
  - 閾値別の時系列回収率・推奨件数
  - 最大払戻除外・上位3払戻除外回収率
  - 単勝30倍超・50倍超採用率
  - 最大ドローダウン、連敗数、払戻集中度
  - 未使用期間での外部評価
  - ライブシャドー評価

## 4. 現行仕様と上位方針の不整合

| 上位方針 | 現行状態 | 判定 |
| --- | --- | --- |
| 大穴を主役にしない | 最大EV選択にオッズ上限なし | 不一致 |
| 単勝30倍超採用率を監視 | 未集計 | 不一致 |
| 最大払戻依存を確認 | 未集計 | 不一致 |
| 未校正確率で高リスク券種を推奨しない | 通常戦で購入推奨 | 不一致 |

## 5. 現時点の運用判定

- 通常戦EV方策: `shadow_only`
- 順位表示: 継続可能
- EV候補表示: 「参考候補」としてのみ保存可能
- 購入推奨・予算全額配分: 再検証完了まで禁止
- 新馬戦方策: 別トラックとして現状維持。ただし今回の集計から除外する。
