# 020-南関東結果API追加実装計画書

## 1. 対象と目的
- 対象機能: 南関東公式結果API
- 改修目的: 既存 `/nankan` のcard/oddsに加え、公式単レース結果と払戻を取得できるようにする
- 今回の対象範囲:
  - `/nankan/races/{race_id}/result`
  - `/nankan/meetings/{date_}/{course}/races/{race_no}/result`
  - `NankanService` result取得
  - `NankanProvider` result取得
  - `nankan_extractors` result parser
  - fixtureと自動テスト
- 今回やらないこと:
  - card/oddsの再設計
  - pattern API変更
  - `/repay` 開催全体払戻API
  - 分析DB収集ジョブへの組み込み

## 2. 実装フェーズ
### Phase 1: 事前確認
- 既存南関APIの現状を固定する。
- 結果ページfixture `nankan_result_2026070419040501.html` を追加する。

### Phase 2: 既存変更単位の特定
- `nankan_provider.py` に `fetch_result` を追加する。
- `nankan_service.py` に `get_race_result`, `get_race_result_by_number` を追加する。
- `nankan_extractors.py` に `parse_nankan_race_result` を追加する。
- `app.py` にresult endpointを追加する。

### Phase 3: 対象プロジェクトの既存パターンに沿った実装
- 既存 `RaceResult` / `ResultEntry` / `PayoutEntry` を使う。
- 既存cacheとrefresh引数の流儀に合わせる。
- 既存 `ResourceNotFoundError` を使う。

### Phase 4: 入口 / 応答 / 設定
- `/nankan/races/{race_id}/result`
- `/nankan/meetings/{date_}/{course}/races/{race_no}/result`
- `refresh` queryを既存card/oddsと同じ扱いにする。

### Phase 5: テスト
- extractorテスト。
- serviceテスト。
- APIテスト。
- 結果未提供404テスト。

### Phase 6: レビュー / 完了確認
- 既存card/odds/patternを変更していないことを確認する。
- 払戻bet_typeが精算処理と合うことを確認する。

## 4. 完了判定
- 実装完了条件:
  - `/nankan/races/{race_id}/result` が存在する。
  - `/nankan/meetings/{date_}/{course}/races/{race_no}/result` が存在する。
  - `RaceResult` に着順と払戻が入る。
  - 未提供結果は404になる。
  - 既存card/odds/patternの挙動を変えない。
- テスト完了条件:
  - `tests/test_nankan_extractors.py` にresult parserテストがある。
  - `tests/test_nankan_service.py` にresult serviceテストがある。
  - `tests/test_nankan_api.py` にresult endpointテストがある。
  - 既存南関card/oddsテストが通る。
- レビュー完了条件:
  - result追加以外の責務拡張がない。
  - 払戻 `bet_type` がcanonical値。
  - source URLが `/result/{race_id}.do`。
